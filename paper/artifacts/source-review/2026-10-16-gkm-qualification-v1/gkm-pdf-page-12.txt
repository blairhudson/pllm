5     Implementation and Evaluation
We implement the client in C++. We start with the open-source LLM inference
software llama2.c [14] (and its fork llama3.2.c [12]) and replace matrix-vector
products and embedding calls with remote server calls. We utilizes AES-NI for
as a pseudorandom number generator (PRNG), SHA256 as the hash function,
and secp256k1 as the underlying cryptographic group. We use arkworks (https:
//arkworks.rs) to implement multi-exponentiations. We reduce communication
for secret sharing by observing that since one of the two shares is uniform, it
suffices to send the seed used by the PRNG to generate the share instead of
sending the share itself.
    We implement the servers in C++ using CUDA to accelerate matrix multi-
plications. We use 16-bit integers to encode weight matrices as fixed-point num-
bers with a scaling factor of f = 2048. We implement a custom CUDA kernel
for computing the product of matrices with 16-bit integer weights and vectors
with 64-bit integer entries, using optimizations from prior work [1].
Experimental setup. We deploy the two servers on GCP VMs each equipped
with 2 A100-80GB GPUs. While we utilize both GPUs for storing the weights,
we do not use multi-GPU parallelization; we only use a single GPU at a time
to speed up matrix-vector multiplications. We deploy server S0 in Ashburn,
Virginia (us-east4) and server S1 in Columbus, Ohio (us-east5). The client C
is an E2 instance with 2 vCPUs and 4GB of RAM located in South Carolina
(us-east1). Ping latency (RTT) and bandwidth between these VMs are: (1) C
and S0 : 12ms, 4Gbits/s (2) C and S1 : 22ms, 3Gbits/s, and (3) S0 and S1 : 7ms,
25Gbits/s. Note that lower latency and higher bandwidth between S0 and S1 is
more favorable to the baseline protocol SIGMA that we compare to, as SIGMA
requires communication between the two servers while our protocol does not but
instead uses more client-server communication.
