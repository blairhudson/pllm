# Ten Low-tier traffic ideas: audited screening results

**No new whole-response all-link saving or Low-tier qualification is established.**
The next implementation candidates are public growing correction epochs, then
exact decode-branch reuse. Their opportunity depends on stopping and reuse
workloads. The examined fresh-request mechanisms are small, negative, or lack a
complete construction.

The common target is a **268,435,456-byte whole-client maximum**, unchanged
checkpoint numerics and privacy, and at least 90% remote body computation in both
prefill and decode. Small scratch buffers, disk-backed data, toy state parity and
arithmetic-body projections do not establish those gates. Each linked screen
retains its own source, workload, accounting and evidence identity; their gains
cannot be added or ranked as one measured cohort.

## Parent audit corrections

* Prepared pruning has one input, one reply and one correction per stage lane,
  each four bytes in the u32 ceiling. The initial absolute ceilings doubled all
  three links without a second execution. Corrected numerator and denominator
  preserve the small 0.1935–0.3888% illustrative body fractions. The larger
  512+8 header screen gives 3,662,848 / 8,372,224 bytes, still with zero input
  savings and no checkpoint traffic measurement.
* Context coding now has a second, disjoint held-out gate. Models freeze from
  original calibration before new reads; complete tables, descriptors, block
  framing and unchanged scales remain charged. Comparing against production-sized
  zlib frames removes the original tiny-frame-control ambiguity. Both frozen
  decoders reproduce all 75 new blocks exactly, but the contextual recipe loses.
* Column placement now has actual source-column observations, beyond histograms.
  The guarded offline parent scan completed after worker investigations. It uses
  the existing exclusive frontier lock, 6 GiB admission and host-pressure guard.
  That research-loader admission is not a Low-tier client measurement.

## Source-column follow-up

[Retained full scan](../evidence/research-column-residue-source.json), SHA-256

A **post-screen public cost selection** may independently choose one of these
four prefixes or zero per stage. Every choice is at most 10% of its stage, so
this restricted optimization obeys the global ceiling without a knapsack
relaxation. It selects five stages, 46,592 local MACs per executed row and 47,044
artifact bytes. Net savings are 16,256 prefill / zero decode / 19,210 combined
bytes. These phase objectives are optimized separately; they are not additive.
Under the same 10% ceiling and raw-layout model, the original exact whole-group
control saves 15,260,684 / zero / 17,642,826 bytes. It owns more client weights;
neither strategy has a measured whole-client peak.

This rejects broad deployment of the tested L1 selector. It does not search every
column subset, prove that another threshold-aware selector cannot work, or price
compressed artifacts, current terminal pruning, actual HTTP controls or SDK
execution. Public weight samples establish integer reconstruction, not complete
decoder logits/KV or transport privacy.

The source scan is reproducible with the existing `--scan-source` command in the
linked note and a fresh output path. The following inexpensive replay reproduces
the post-screen selection from the committed scan without loading weights:

```python
import json
from pathlib import Path
from scripts.probe_column_residue_placement import baseline

scan = json.loads(Path("docs/evidence/research-column-residue-source.json").read_text())
geometry = json.loads(Path("docs/evidence/research-narrow-ingress.json").read_text())
stages = {s["stage"]: s for s in geometry["checkpoint_geometry"]["stages"]}
for rows in (150, 7, 157):
    total = 0
    for observed in scan["held_out_source_column_validation"]["stages"]:
        stage = stages[observed["stage"]]
        n, m = stage["shape"]
        gains = [0]
        for point in observed["points"]:
            k = point["columns"]
            delivery = n * k + 64 + 4 * k
            remaining = ((m - k) * point["request_bits"] + 7) // 8
            remaining += 2 * ((point["remote_bits_sum"] + 7) // 8) + 3 * (64 + 16)
            gains.append(rows * (baseline(stage) - remaining) - delivery)
        total += max(gains)
    print(rows, total)
# 150 16256
# 7 0
# 157 19210
```

## What to pursue next

1. **Public growing epochs.** Extend the existing fixed-epoch contract with an
   immutable predeclared schedule, preserving authenticated retirement before
   idle Preparation and exact pending-token/RNG/full-KV continuity. Then measure
   matched early/full stopping workloads against the best fixed policies. Price
   full-cap memory even when most requests stop early.
2. **Exact decode reuse.** First show native logits/KV/sampler parity across
   branches, EOS, restart and cancellation against installed generated-prefix
   reuse. Admission must discover reusable execution before paying fresh
   correction issuance. Already issued or reserved material remains charged.
3. **Workload-specific public artifacts.** Atlas retrieval needs an actual
   multi-client public catalog and its privacy composition; update deltas need
   authenticated real revision pairs. Their conditional models do not improve
   unrelated first-cold private requests.

The frozen cache/codec recipes, tiny pruning/column increments, cancellation cuts
and binary-slice target do not currently justify serving integration. The earlier
[fixed-W correlation compiler gap](correlation-cartridge-frontier-reference.md)
also remains open; these screens supply no substitute construction.
