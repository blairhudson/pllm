# Cold request: hierarchical token-block decoding

## Conclusion

**Plausible architectural research direction, not an exact-checkpoint execution
optimization and not serving-ready.** A *trained* global/local language model can
run its expensive global trunk once per causal patch while its local decoder
runs autoregressively for every original token/byte. Existing target rows do not
disappear: this is a new model assigning a new distribution. Downloading even a
small local encoder, decoder and vocabulary can dominate one short cold request.
There is no evidence here for natural-language quality, a complete trained patch
schedule, WAN speedup, or an unconditional `1/k` byte saving. **Primary public-weight
candidate can reuse prepared masked-linear placement with client-owned global
nonlinear work and KV. Protected provider-held nonlinear/KV is not required.**

The executable fixture is deliberately **untrained**, bounded and independent of
the SDK. It demonstrates causal dependencies, sampling, feedback and accounting;
it cannot demonstrate the missing trained architecture. No checkpoint load,
training, timing cohort, build or installation was performed.

## Primary literature: concrete designs and limits

Versioned raw HTML hashes and byte lengths are frozen in
[`cold-block-decoder-synthetic.json`](../evidence/cold-block-decoder-synthetic.json).
Hashes describe the fetched HTML, not a locally retained PDF or immutable arXiv
rendering. Offline replay checks local implementation sources; online source
verification requires fetching the exact URLs again and checking the recorded
hashes. HTML rerendering can change a hash without changing scientific content.

1. **[MegaByte, Yu et al., 2023](https://arxiv.org/html/2305.07185v2)**,
   §§2.1–2.4, 3.2, 8.4, Figures 1–2. Fixed patches; shifted previous-patch
   embeddings enter a global causal transformer; projected global output plus
   shifted byte embeddings enter a small *autoregressive* local transformer.
   Compatible public-weight split: client patch embedder/local decoder plus client
   global attention/nonlinear/KV; provider-owned global matrices execute masked
   linears, using Preparation offline. Feedback must encode the **sampled completed patch**, not a
   guessed future patch. Global width can grow with patch size (`P*D_G`), so one
   larger latent is not a constant-cost object. §2.4 explicitly rejects independent
   heads using the “cat/dog” mixed-string example. §8.4 strided inference doubles
   global work; sliding plus striding costs 4×. Charge those passes if needed for
   quality. The paper's sizable local models are not free consumer downloads.
2. **[Byte Latent Transformer, Pagnoni et al.](https://arxiv.org/html/2412.09871v1)**,
   §§2.3–2.4, 3.1–3.3, 4.2, 4.5–4.6. Local byte encoder pools representations into
   patches; global transformer processes patches; local decoder cross-attends to
   global representations and uses previously decoded bytes. Cross-attention,
   local sliding-window KV, encoder hash n-gram tables and boundary predictor all
   need ownership and cost. Entropy patching uses a separate small model (100M
   parameters in §4.2), itself downloaded/initialized if client-local. Incremental
   patching cannot inspect future generated bytes. Ordinary BPE is not incremental:
   future text may retokenize the prefix. Compatible first prototype: fixed stride,
   rather than treating a corpus-average entropy patch length as guaranteed `k`.
   Report bytes and original baseline-token counts separately; patches are neither
   bytes nor baseline tokens. Bits-per-byte, not cross-tokenizer perplexity, compares
   likelihood across byte/token models.
3. **[Better & Faster LLMs via Multi-token Prediction, Gloeckle et al., 2024](https://arxiv.org/html/2404.19737v1)**,
   §2 inference, §3.2, Appendix B. Independent future heads share a trunk;
   speedup uses **self-speculative verification**, not guaranteed emission of all
   head samples with the main head's autoregressive law. Training helps proposals;
   it does not remove target verification or establish byte savings.
4. **[DeepSeek-V3 Technical Report](https://arxiv.org/html/2412.19437v1)**,
   §2.2, Figure 3, equations 21–25. Sequential MTP modules combine preceding
   depth representation with next-token embedding, preserving a causal chain.
   This supplies a useful trainable adapter template; paper inference discards
   those modules or uses them for **speculative decoding**. Deploying them as an
   unverified local authoritative decoder would create a different model and
   requires separate training/quality qualification. MLA compresses KV, not the
   original token update schedule into free multi-token emission.

The existing [checkpoint drafter reference](checkpoint-drafter-reference.md)
preserves target greedy execution through verification. Two/four-token proposals
reduced dependent calls but increased target rows and ring-body estimates by
8.35%/14.90%. This proposal must not relabel those rejected rows as skipped work.
No independent-head or hierarchical quality result establishes exact Qwen W8A8
`prefix_f32` logits, tokens, stochastic distribution or KV parity.

## Trainable architecture still missing

For fixed stride `k`, a valid split can have:

```text
e_j = E_local(x in completed patch j, causal local encoder state)
(z_j, K_global[j]) = G_public_prepared(e_<j, K_global[<j])
x_(j,r) ~ D_local(z_j, sampled x_(j,<r), retained local state)
```

The index shift matters: current patch targets must never enter `z_j`. At each
boundary, encode actual selections, send protected `e_j`, then execute the next
global update. Prefix-dependent entropy boundaries must be decided before the
next byte is sampled, using only available causal state. EOS belongs to the
model's vocabulary and sampling law. Final length-limited patch is partial, not
silently padded with future tokens. An explicit prompt boundary/delimiter must be
part of training if generation closes a partial prompt patch; otherwise retain
and continue that patch. Fixture uses explicit prompt boundary semantics.

Need jointly trainable encoder, global trunk, cross-attention/projection, local
causal decoder, output head, EOS and boundary policy, plus pinned quantization and
numeric mapping. Token-level version can retain original tokenizer; byte version
must carry a baseline tokenizer/counting artifact if baseline token counts are
required. Frozen public local weights are acceptable only if model owner permits
that release. Distillation/finetuning is a new checkpoint identity, not proof of
same-model execution. Training resource/energy belongs in a separate development
ledger, not hidden in a serving-request saving claim.

## Protection and actual masked execution compatibility

No TEE. **Primary composition is public weights, private client input.** Current
public PLLM prepared placement keeps private nonlinear work and KV at trusted
client and delegates only masked linears. For a trained patch Transformer, client
can likewise own global patch KV, attention/softmax, norm, activation/rescaling,
local encoder/decoder, sampling RNG and decoded block latents. Public weights mean
client latent decoding needs **no new permission flow**. Global body matrices
remain provider-owned/resident; public provenance does not imply downloading them
to the client. Preparation supplies offline stage correlations/corrections.

All representations crossing remote boundaries stay protected: masked stage
inputs/outputs and opaque preparation material, never clear private patch embeddings
or sampled-token feedback at providers. Encoding a completed sampled patch is
client-local; its first global linear input is masked under the prepared schedule.
Global KV never needs a provider transfer in this composition. Client can unmask a
linear output, run nonlinear work locally, then freshly mask the next linear input.
TLS alone is insufficient, but provider MPC softmax/KV is not a baseline gate.

Still missing: trained source/checkpoint and patch adapter/loader, exact block-causal
and positional/numeric schedule, per-stage correlation binding and admission,
sampling-feedback lifecycle, full cold artifact/wire ledger and quality. Existing
masked dense-decoder support provides a **placement template**, not direct BLT or
MegaByte support. `real_masked_transformer_compatibility=false` means no complete
trained patch execution has been implemented here, not that this public placement
requires new provider-held secure nonlinear machinery.

**Distinct alternative: provider-resident share/KV architecture.** Affine fixture
below simulates that alternative, not baseline PLLM placement. Additive masks cannot
pass unchanged through remote softmax, normalization, SiLU, rescale or private-weight
products. A genuine provider-resident Transformer would require those protected
operations, attention and KV protocols. Their byte/CPU costs are **unknown and must
be added**, not absorbed into affine costs or assigned zero. Evidence marks this
alternative blocked by missing cost/implementation; those gates do not apply to
client-owned nonlinear/KV placement. Noncolluding providers require distinct trust
domains, not two workers controlled by one owner.

**Separate private-weight composition:** a private global latent may reveal model
information to the client. If model owner restricts latent release, negotiate that
interface or retain shares through secure local decoding, charging all additional
MPC work. This is not a primary public-target permission requirement. Fixture uses
public toy weights and proves no private-weight secrecy.

### Bounded primary public prepared-placement screen

`public_prepared_screen()` independently projects a two-layer public toy global
Transformer: hidden 32, two KV heads of width 8, unfused q/k/v/o + gated MLP (width
64), four-byte ring bodies, 64-byte stage frame headers. No model is loaded; no
SDK support is inferred. Client holds global nonlinear/KV, public local modules
and latents; provider holds global body matrices; Preparation holds offline stage
material. Evidence lists ownership, stage dimensions and complete selected
body/header/download ledger inputs. No provider KV or nonlinear traffic is imposed.

For each charged global row and stage `(a,b)`, online input/output bodies are
`4*a + 4*b`; offline output correction is `4*b` per reserved row, including unused
rows. Three stage frames are charged for a used row. This is the existing prepared
placement's input/output/correction **geometry template**, not a serialization
measurement. Real mask issuance, any extra Preparation links, artifact/TLS framing,
warmup, ACKs and retries must replace or extend these inputs. Completed-patch
feedback enters the next masked first-stage input, already charged; there is no
additional clear feedback channel. Final partial feedback/state bookkeeping is
client-local in this placement. If final global KV is computed for audit or a
continuation contract, charge its extra linears rather than importing a free
provider commit from the alternative fixture.

Conservative illustrative caps: 39 prompt tokens and 32 outputs, fixed stride four,
explicit prompt boundary, ten prompt patch rows + eight decode rows. These are
chosen schedule caps, **not** exact baseline executed-row parity or fitted BLT
statistics; a real prefill/first-output/final-feedback schedule may reuse or add
rows. Shape-only global KV capacity:

```text
KV_slot_bytes = 2 * layers * KV_heads * head_dim * element_bytes
full_token_global_capacity = (prompt_tokens + output_tokens) * KV_slot_bytes
patch_global_capacity = (ceil(prompt/k) + ceil(output/k)) * KV_slot_bytes
```

Matched global KV geometry yields 256 bytes/slot: full-token capacity **18,176
bytes** (71 slots), patch capacity **4,608 bytes** (18 slots). Add hypothetical
two-layer local encoder and decoder KV windows of eight tokens each: **2,048
bytes each**, giving **8,704 bytes** total global+local KV. Current 32-wide client
latent adds 128 bytes separately. These are derived capacity bytes, not measured
RSS or actual checkpoint sizes. Windows, KV head geometry and global width are
not guaranteed constant across trained architectures. At `k=1`, global KV saving
vanishes while local windows still add memory.

No weights, attention/cross-attention scratch, allocator overhead, local hash tables,
startup peaks or prepared masks/correlations are included in KV geometry. In
particular, client global attention and nonlinear work remains real per-patch CPU;
larger patch width/global parameters or local tables can overwhelm KV savings.
Consumer admission must use full runtime peak, not this KV-only ratio. All sizes
here are integer accounting; zero checkpoint or large-array allocation.

## Executable causal fixture: provider-resident alternative

`scripts/probe_cold_block_decoder.py` uses only Python stdlib, vocabulary `{0,1,2,
EOS}`, two-coordinate states in field 257, and public affine global weights.
Private ordered feedback encoder includes both token order and actual length.
Two simulated noncolluding providers receive fresh additive feedback shares and
retain only additive state/KV shares; output shares reconstruct at trusted client.
Independent clear arithmetic checks every global output and final state. Sampling
RNG is independent of masking RNG. Seeds are reproducible and **not cryptographic**;
in-process harness sees both shares. No network security or private LM execution
is claimed. Exhaustive mask test establishes only the one-coordinate uniform-share
control when masks really are uniform and unknown, not deterministic-mask security.

Local categorical distribution depends on global latent, previous sampled token
and patch position. Local state keeps last `k` selected/prompt tokens. At most 64
prompt/output tokens and `k<=16`; zero additional numeric arrays. All 128MiB decoder
download scenarios are integer accounting, not allocations.

Fixture checks:

- Longer future request cannot affect first block or already sampled prefix.
- Changing selected intra-block token changes next local distribution.
- Next global forward refuses absent sampled-block feedback; different/order-swapped
  feedback changes global state and next latent. A stale global result is invalid.
- Every selected token costs one local decoder row; all global prefill/forward and
  feedback commits remain counted. `k=1` is a different toy architecture, **not**
  original-target parity or a task-quality-matched control.
- Greedy and categorical replay; natural toy sampled EOS plus controlled first/mid/
  boundary/final EOS hazards. Injected EOS is a scenario, not learned EOS performance.
- EOS stops remaining local rows but cannot refund issued global update or reserved
  correlations. Includes EOS in selected-token count, not necessarily rendered text.
- Final partial block commits exactly its real tokens. Final commit deliberately
  retained/charged for state audit; a no-continuation API could discard KV instead,
  but must measure that explicit lifecycle rather than reuse savings later.
- Eager cancellation after a global issue wastes one update when cancelled before
  local sampling or exactly at patch boundary. No empty block enters KV. Mid-block
  cancellation commits only selections already emitted. Session then discarded.
- Request reserves full horizon plus optional extra unused preparation. No future
  representation is validly precomputed without unknown sampled feedback; only
  input-independent fresh masks/keys can be prepared early. Unused keys are burned.

Independent-head counterexample: first bit uniform; second copies first. True
autoregressive joint places 1/2 each on `00`,`11`. Independent exact marginals place
1/4 on all pairs, yielding impossible-sequence mass and total variation **0.5**.
No amount of correct per-position marginal estimation fixes missing causal coupling.

Provider KV here is an affine recurrence journal, **not transformer KV**. It grows
one committed row per prompt patch plus actual emitted block. Empty cancelled
forward does not append KV; partial/EOS feedback does. Real model needs per-layer
global patch KV and local encoder/decoder windows, cross-attention caches, masks,
offsets, truncation and teardown; count those separately in measurements.

## Alternative fixture one-request cost model (hypothetical geometry)

Every scenario is an independent fresh request. No local weights, tokenizer,
preparation or setup is amortized across future requests. Provider model is already
deployed, as in baseline serving; `provider_provisioning` must be populated if this
request provisions any new provider artifact. Download includes separate encoder,
decoder, vocabulary embeddings/head, tokenizer, numeric tables and manifest.

Let `P` be charged prefill global rows, `B` issued decode forwards (including empty
cancelled forward), `F` all actual feedback commits including prefill/final, `R`
all reserved preparation rows including unused. Fixture charges a global row for
each prompt patch even though its affine prefill is simpler than a transformer.

```text
C_cold = decoder + encoder + vocab/head + tokenizer + tables + manifest
       + setup_up + setup_down + provider_provisioning
       + (P+B)*(forward_up + forward_down + forward_peer)
       + R*preparation_download
       + F*(feedback_up + feedback_peer)
       + headers/ACKs + close_up + close_down
```

Fields are aggregated all-link bytes across both parties. Global down body includes
protected block output; no second free/clear latent channel. Preparation download
assumes both-party keys/correlations included. Feedback includes initial prompt
encoding and final partial commit. Header geometry is six frames per global row,
four per feedback, two per prepared row, four setup/close frames. Public lengths
and stopping time leak in this hypothetical schedule; length-hiding padding must
increase these ledger inputs. Hypothetical peer link traffic is counted even if
not on client bottleneck. Real TLS/HTTP framing, ACK bodies, padded ciphertexts,
retransmits, correlations from every operator, and artifact headers must replace
these inputs; currently **no byte figure is measured**.

Global rows, feedback MACs, per-token local decoder/encoder MACs, two-party KV
residency and dependency rounds are separately recorded. No skipped original
target work is asserted. Local output-head cost must be included in configured
decoder MACs; embedding/head weights cannot be omitted. Latency expression is a
serial no-overlap arithmetic screen:

```text
T_screen = C_cold / aggregate_link_rate
         + dependent_rounds*RTT + local_MACs/local_rate + provider_MACs/provider_rate
```

It is not a bound/measurement: asymmetric links and overlap change it. Download
loading/decompression, tokenization, key-generation/issuance, cryptographic operator
CPU, memory pressure and startup time are **unknown**, not zero runtime. They must
be measured before a latency claim. This is a full configurable byte ledger for
the chosen hypothetical contract, not a complete real cryptographic cost result.
For provider-resident Transformer, protected nonlinear/attention/KV costs remain
explicitly unknown; affine ledger is insufficient and must not be promoted. Primary
public prepared screen above instead charges its masked global stages and retains
nonlinear/KV work at client, whose CPU/admission is still unmeasured.

Cold saving requires reduced global **total** execution/preparation bytes to exceed
extra local downloads, feedback, unused material and setup. Larger `k` may increase
latent width/global parameters or require extra strided passes. Existing unmodified
prompt prefill does not automatically become `ceil(prompt/k)`; only a genuinely
trained patch architecture earns that schedule. Quality failure cannot be repaired
by granting arbitrary compression for free. Evidence includes decoder-download
sensitivity at 1/32/128MiB without allocating those weights.

Frozen illustrative examples (decimal bytes, **not observations**):

| Scenario | Selected original tokens | Prefill / decode global rows | All-link bytes | Unused preparation bytes |
| --- | ---: | ---: | ---: | ---: |
| New toy architecture `k=1` | 32 | 39 / 32 | 13,337,600 | 0 |
| New toy architecture `k=4` | 32 | 10 / 8 | 7,435,520 | 0 |
| First-token EOS, horizon reserved | 1 | 10 / 1 | 7,115,648 | 458,752 |
| Cancel before local sampling | 0 | 10 / 1 | 7,103,104 | 458,752 |
| Cancel at four-token boundary | 4 | 10 / 2 | 7,148,800 | 393,216 |
| Final partial request, cap 10 | 10 | 10 / 3 | 6,878,720 | 0 |

These architectures do not have matched distributions or held-out task quality;
table is not a baseline promotion comparison. With `k=4` unchanged, varying decoder
download from 1MiB to 32MiB to 128MiB changes cold total to 4,289,792 / 36,795,648 /
137,458,944 bytes. Thus a fourfold decode-step reduction is neither a fourfold
cold-byte reduction nor sufficient to overcome arbitrary decoder download.
MAC rates are aggregate provider/local screen inputs, not per-party throughput
measurements; choose aggregated two-party work rather than counting one free party.

## Minimum quality gate and serial-parent measurement plan

For primary public target, first obtain trained architecture/checkpoint with public
local modules and pin source/numeric/patch schedule. Use current prepared placement
for global masked linears with client-owned global KV/nonlinear work; no latent
permission flow or provider secure nonlinear/KV implementation is required. Need
complete adapter/schedule, full bytes/admission and quality, not direct BLT support.
Provider-resident alternative separately needs protected nonlinear/KV costs;
private-weight latent-release policy is a separate composition gate.

1. Freeze model/tokenizer revisions, quantization, `k`, prompt-boundary behavior,
   entropy/striding policy, EOS/sampling, length caps, latency/byte quality targets.
   Use separate training/tuning and held-out identities; publish hashes.
2. Minimum pilot: 200 disjoint held-out prompts, 50 each natural text, executable
   code, exact-answer arithmetic and multilingual/Unicode. At least half require
   cross-patch dependencies; include every boundary offset, short responses and
   EOS/partial-block cases. Add fixed held-out text for bits-per-byte (same-token
   perplexity only if tokenizer unchanged). Compare against pinned original model
   and a same-budget independently trained baseline; greedy plus fixed-seed
   categorical sampling. Report task pass/exact match, BPB, response length,
   termination rate and paired bootstrap 95% CIs. Predeclare tolerances (e.g.
   <=2 percentage-point task drop, <=5% BPB increase); pilot too uncertain to pass
   means collect more samples, not assume equivalence. No oracle test temperatures.
3. Separately require exact replay of **new** model's unmasked pinned integer
   oracle vs protected schedule for all logits/selections/global+local KV under
   chosen arithmetic. This checks implementation identity, not original-model
   quality. Include malicious/replay failures if threat model requires them.
4. Parent alone admits serial runs under existing measurement lock; no parallel
   checkpoints/training/timing. Fresh process/client cache each sample, at least
   three per qualified option. Use installed env; do not install/build as part of
   this worker. First dry-run bounded shapes, four CPU threads, predicted residency
   below parent's available physical-memory ceiling, no swap-growth admission;
   if needing large pretrained BLT/MegaByte, stop and request explicit resource
   authorization. Do not treat this worker's 128MiB-array bound as permission to
   load a multi-GB checkpoint.
5. Measure exactly one request per sample: download bytes/time for all local
   artifacts, cold import/load/tokenizer/setup/issuance CPU, prefill, each remote
   stage's directed bodies/framing, applicable peer traffic, latents, feedback, preparation
   issued/consumed/burned, local decoding CPU, final teardown, peak RSS and swap.
   Record original baseline tokens, bytes, patches, actual global rows, local
   rows and rejected/unused work. Separate time-to-first-token, completion time,
   full process lifetime and task quality. WAN RTT/asymmetric bandwidth runs only
   after patch schedule runs through actual prepared protected transport. Attribute
   client global attention/nonlinear CPU and global patch KV separately from local
   encoder/decoder windows and preparation residency; measure actual peak rather
   than treating derived KV capacity as memory admission. Replay EOS and cancellation at each
   stage boundary. No future-cache credits.
