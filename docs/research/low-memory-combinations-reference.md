# Low-memory prepared combinations

This screen searches ordinary installed SDK recipes under the **256 MiB maximum
client RAM** tier. The control already includes 64-row MLP tiling and digit8
Preparation. Its five neighbors change only tile geometry and the previously
frozen selective placement.

## Frozen design

| Case | Prefill tile rows | Preparation | Selective placement |
| --- | ---: | --- | --- |
| control | 64 | paged digit8, `min_rows=64` | None |
| tile32 | 32 | Same | None |
| tile16 | 16 | Same | None |
| placement | 64 | Same | 38 layer/role groups |
| tile32-placement | 32 | Same | Same 38 groups |
| tile16-placement | 16 | Same | Same 38 groups |

The pinned Qwen2.5-0.5B-Instruct W8A8 source, `prefix_f32` numeric contract,
indexed tokenizer, paged client weights, packed/residue arithmetic, terminal
pruning, sixteen-row duplex prefill, demand inventory and exact-repeat cache are
shared. Placement retains at least 90% of body linear MACs remotely, checked
independently for prefill and decode.

Each 150/288-input-token workload produces eight outputs per request. Each cell
owns one fresh client and two prepared role children, executes a cold request
then its exact repeat, and retires its owners. Three balanced serial replicates
per recipe/workload give 36 clients and 72 responses under shared native
100/40 Mbps caps. The 150-token workload uses four-stage/64 MiB issuance; the
288-token workload uses serial issuance. Comparisons stay within each workload.

Smaller tiles bound intermediate tensors but add dependent stage exchanges.
The digit8 threshold still applies to the original full correction jobs, not
the client's individual execution tiles. Repeat cache hits bypass prefill
tiling and retain their own timing observations.

## Evidence gates

Low eligibility requires the **largest** recorded client process-lifetime peak
across every planned replicate to fit 268,435,456 bytes. Medians remain the metric
summaries; missing, failed or duplicate replicates cannot qualify. Unknown peaks
stay unknown. A process peak includes both cold and repeat requests, relay and
SDK overhead. GPU memory, filesystem cache and other application processes have
separate owners. Observed eligibility does not replace conservative SDK or
whole-topology admission.

All comparisons require matching source, numeric, workload, output, privacy and
measurement commitments. Cold and repeat TTFT/decode remain separate. Client
cold-first CPU, Preparation birth-to-first-response CPU, request-window sampled
Preparation RSS and cold-plus-repeat TCP traffic retain their original windows.
Known base, output-dependent and residual application-body bytes must conserve
the covered total; residual bytes keep complete traffic headlines unknown.
Checkpoint/tokenizer distribution, physical wire, Internet RTT and cleanup
CPU/time are outside the measured response windows. Earlier cohorts are separate.

Generated Qwen2, Qwen3 and Llama checkpoint checks cover 64/32/16-row tiles,
digit8, placement, exact logits/KV, repeat cache hits, gateway responses and
failure retirement. The installed-wheel test selection passes 37 checks.
These checks establish functionality, not real-checkpoint performance.

## Replay

`benchmarks/research/low_memory_combinations.py` constructs immutable targets
using the same response benchmark, admission and audits as the previous screen.
`scripts/benchmark_low_memory_combinations.py` retains the exact build, source
hashes, fixture derivations and preflight. Outputs must be fresh; the common
private cohort salt is generated by the benchmark runner.

```sh
python -m pytest -o pythonpath= tests/test_low_memory_combinations.py tests/test_sota_combinations.py tests/test_sota_combination_execution.py -q
python scripts/benchmark_low_memory_combinations.py --tiny --processes 1 --output target/low-memory-smoke-new.json
python scripts/benchmark_low_memory_combinations.py --preflight-only --output target/low-memory-admission-new.json
```

Use an installed release wheel and the source-locked indexed-tokenizer artifacts
from `target/prepared-frontier-artifacts`. Replay requires the original Python
build path and matching frozen measurement sources. A fresh rerun receives a new
salt; it cannot extend or pool the prior cohort.
