# WAN-constrained throughput: five method screens

## Matched primary cohort

The ordinary multi-Experiment benchmark ran four candidates sequentially under
one private cohort salt. Pinned Qwen2.5-0.5B-Instruct revision
`7ae557604adf67be50417f59c2c2f167def9a775`, W8A8 `prefix_f32`, greedy selection,
39 input tokens and eight generated outputs. Every output hash matches.
All four runs use the same measured integer body and runtime image.
Source locks agree within each role graph; both locks are retained.

Each party, including the client, has one shared **100 Mbps download / 40 Mbps
upload** budget across all peers. Linux queues additionally apply 20 ms egress
delay per party: 40 ms added request/reply delay, before topology overhead.
Delay, loss and bandwidth readbacks must match the selected profiles.
A separate echo test observed approximately 52 ms RTT on this local topology.
No packet loss was selected.

| Candidate | Full request s | End-to-end tokens/s | Decode tokens/s | Client request CPU s | Covered setup MB | Online MB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Prepared control | 122.87 | 0.0651 | 0.1976 | 20.44 | 236.601 | 71.193 |
| Coalesced artifacts + preparation window | 104.73 | 0.0764 | 0.1984 | 21.24 | 236.559 | 71.193 |
| Seeded/packed offset control | 155.01 | 0.0516 | 0.1027 | 24.08 | 236.996 | 112.005 |
| Seed-first offset | 105.33 | 0.0760 | 0.1994 | 19.86 | 236.996 | 112.005 |

Prepared overlap raises request TPS **17.3%**, primarily by reducing measured
preparation/delivery time from 59.96 to 43.26 seconds. Client request CPU rises
3.9%; recorded aggregate request CPU changes from 43.72 to 43.01 seconds.
Seed-first offset raises request TPS **47.2%** and decode TPS **94.1%**. Its
client request CPU falls 17.5%, and recorded aggregate request CPU falls from
44.69 to 40.46 seconds. Online application bodies are unchanged in both pairs.
The 48-byte offset setup difference is control/measurement serialization, not
an arithmetic-body reduction.

End-to-end TPS includes demand preparation and client bundle delivery but
excludes provider startup and checkpoint distribution. Decode uses the seven
outputs after the first, divided by measured first-to-last-token time. CPU
figures cover the request window, not deployment startup, helper processes or
all kernel/system work. These are single samples, not latency distributions.
No cross-topology privacy/compute-cap winner is inferred from the table.

## Five methods and promotion decisions

1. **Seed-first rendezvous.** `TwoOnlineOffsetLinear(input_encoding="seeded",
   output_encoding="row_residues", dispatch="seed_first")` sends the independent
   worker's seed before native complement construction and the other worker
   exchange. One session-owned sender is shut down after cancellation/completion;
   partial failures burn both sessions. Exact same masks, public ring contract
   and linear arithmetic; no client body weights. Promoted as an explicit choice.
2. **Public entropy coding.** Four-state byte rANS, native bounded frames and
   raw fallback preserve exact bytes. For the 145.98 MB public bundle, framed
   zlib uses 124.900 MB versus rANS's 127.748 MB. Server encoding CPU falls
   3.944→0.636 s, but client decoding grows 0.514→0.681 s. More bytes and client
   work fail the intended gate. `ArtifactEntropyProbe` remains a research API;
   no rANS runtime delivery option is enabled.
3. **Coalesced public artifacts.** `ClientBundleTransport("artifacts",
   compression="zlib", batch_objects=64)` collects missing small objects under
   a 1 MiB raw-group bound. The response binds the ordered key set, encoding and
   lengths; every original object hash is checked before cache insertion.
   Large objects retain ordinary streaming. Raw/zlib and prepared/verified/
   offset paths pass. Unknown compressed-batch transfer costs are not silently
   priced as the sum of independently compressed objects by the planner.
4. **Windowed preparation.** `PreparedInventory("request-sized", rows=1,
   refill="on-demand", stage_window=4)` overlaps independent issuance and push
   acknowledgements. Native work stays unchanged. A conservative 16 MiB active
   work estimate and four-operation limit bound lookahead; acknowledgements are
   checked against their stage commitments before sealing. Cancellation burns the
   inventory before joining workers,
   including queued/late material. An oversized stage fails before issuance.
   No preparation starts during online execution.
5. **Duplex masked prefill.** `MaskedLinear(output_encoding="row_residues",
   prefill_chunk_rows=4)` sends fixed, disjoint row chunks over one duplex
   WebSocket. Frame count and bytes are bounded; no HTTP retry follows accepted
   work. Session/model/request/sequence/HMAC checks reject reordering. Freivalds
   verifies the assembled integer result before dequantization. Native codecs
   and kernels remain the hot path. Tiny logits/KV and pinned functionality
   pass, but separate exploratory runs show a small and inconsistent incremental
   TPS benefit. Exposed explicitly; not selected automatically or recommended as
   a measured whole-response winner.

The four sampled native projection shapes in `PreparedDuplexProbe` match exact
integer outputs at every chunk width. The optimistic stage model suggests useful
prefill overlap, but excludes transport scheduling and decoder work; it does not
predict an established whole-response speedup. One-row decode cannot overlap
rows. This distinction prevented promoting the projected gain as measured TPS.

All live choices retain zero client body-weight and native body-snapshot bytes
in the retained reports. Bounds are **not** measured peak client memory. Public
token-boundary storage still exists. Co-located services do not establish
non-collusion or independent deployment. Routed IP-hook counters and application
bodies do not establish full physical-wire accounting. **10× remains unmet.**

## Reproduce and inspect

From the repository root with the installed native build and Docker:

```bash
uv run --no-sync python -m pllm benchmark run \
  --experiment examples/benchmarks/wan_tps.py:prepared_control \
  --experiment examples/benchmarks/wan_tps.py:prepared_combined \
  --experiment examples/benchmarks/wan_tps.py:offset_control \
  --experiment examples/benchmarks/wan_tps.py:seed_first \
  --trust-python --wan \
  --docker-network-profile examples/benchmarks/wan-40ms.json \
  --warmups 0 --repetitions 1 --max-output-tokens 8 --temperature 0 \
  --capture-output-digest --timeout 300 \
  --output docs/evidence/wan-tps-matched-qwen25-2026-10-04.json
uv run --no-sync python scripts/summarize_wan_tps.py \
  docs/evidence/wan-tps-matched-qwen25-2026-10-04.json \
  --output docs/evidence/wan-tps-qwen25-2026-10-04.json
uv run --no-sync python scripts/probe_wan_methods.py --method entropy --real \
  --output docs/evidence/wan-tps-entropy-qwen25-2026-10-04.json
uv run --no-sync python scripts/probe_wan_methods.py --method duplex --real \
  --output docs/evidence/wan-duplex-qwen25-2026-10-04.json
```

The summary recomputes WAN and byte metrics, checks workload/numeric/output
identity, verifies source identity within each role graph, and hashes its source
report. Single-invocation exploratory reports have distinct salted prompt hashes;
the summarizer rejects treating them as one matched cohort. Those reports are
retained as diagnostics, including the duplex/all-options run, but do not enter
the primary table. One confirmation attempt found a removed cached Docker image;
automatic rebuilding completed the later runs. The final four-way cohort uses
one image for all candidates.

Validation includes native entropy frame/round-trip tests, compiler default-
schedule identity, bounded preparation concurrency and cancellation, atomic
artifact verification, duplex flow/deadlock/malformed-frame tests, exact tiny
prefill/decode logits and KV across prepared/verified/offset choices, and the
ordinary gateway. Independent security review and broad generation quality are
outside this measurement.
