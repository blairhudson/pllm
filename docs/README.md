# Fumadocs documentation

This directory is the actual Next.js / Fumadocs application, not a generated
reading preview. It uses pinned direct dependencies, MDX content, system fonts,
browser search and static output.

From the repository root:

```bash
make paper
uv run --no-project --python 3.13 python scripts/prepare_docs.py
cd docs
npm install
npm run dev
```

After generating and committing `package-lock.json`, use `npm ci` instead.

```bash
npm run check:content
npm test
npm run typecheck
npm run build
npm run preview
```

A production export is emitted to `out/`. To validate project Pages deployment:

```bash
NEXT_PUBLIC_BASE_PATH=/pllm npm run build
```

`NEXT_PUBLIC_BASE_PATH` prefixes static downloads, search fetches and raw HTML
links. Next.js adds the same prefix to its route links. The Pages workflow reads
this value from the actual GitHub Pages configuration, so account names and
repository names are not hardcoded.

## Editing

`content/docs/` contains documentation; `content/home.html` and
`content/research.html` are trusted repository templates. `public/brand.css`
contains the design system. `components/site-chrome.tsx` provides search,
keyboard shortcuts and the theme switch. No analytics service or model endpoint
is contacted by the site.

The paper PDF and article are generated by `../scripts/build_paper.py` from
`../paper/manuscript.md`. Run `../scripts/prepare_docs.py` after compiling the
paper to refresh downloadable paper, source and evidence. `scripts/generate.mjs`
produces the static search index and Markdown exports from MDX.

The repository includes a real semantic typecheck and framework build in CI.
Neither the configured workflow nor the content tests imply that a remote
GitHub deployment has already happened.
