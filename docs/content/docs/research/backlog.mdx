PLLM tracks papers because they may improve a concrete protocol, compiler pass,
numeric primitive, or state-management boundary. A tracked paper is not a PLLM
implementation. A similar data flow is not a reproduction.

The [scorecard and chronology](/research/papers/) now distinguish measured SDK
adaptations from bounded component references and unimplemented systems, with a
filter for implemented work. [Rerunnable Python configurations](/research/scorecard/)
bind each score to its matched cohort. Newly added work includes Curl's bounded
shared lookup and public Haar compression; protected truncation, distributed
issuance and decoder integration remain open. SmoothQuant's existing public
channel-equalization adaptation is now indexed explicitly.

## Composition and search

Papers do not become isolated runtime stacks. Each reimplementation contributes
one or more components to a stable capability family: model and cache
transformations, linear or nonlinear protocols, protected representations,
conversions, preparation schemes, kernels, placement policies, assurance checks,
and benchmark objectives. Like-for-like implementations live together behind
the same typed contract; paper IDs remain provenance, not architecture.
This is an evolving taxonomy. A genuinely new semantic role, lifecycle, or type
boundary can introduce a new capability family; a new paper alone cannot.
Families may split into dedicated modules as their implementation libraries grow
without changing their stable plan contracts.

The harness will explore combinations in stages. It first rejects incompatible
numeric domains, party topologies, trust assumptions, state lifetimes, model
coverage, and devices. It then uses exhaustive or grid search for small bounded
spaces and reproducible seeded random search for larger conditional spaces.
Adaptive search can follow when enough comparable evidence exists. Every
candidate still compiles into an immutable plan and passes correctness, privacy,
execution, and evidence gates before its performance enters a comparison.

Search is multi-objective. Correctness and privacy are hard constraints; latency,
throughput, traffic, memory, preparation cost, quality, energy, and monetary cost
remain separate measurements. PLLM records a Pareto frontier for one matched
cohort rather than declaring one method universally best.

## Fresh-prompt network gate

For the pinned 39+32 W8A8 Qwen cohort, measured covered all-link bodies are
178.97 MB; a 10× improvement needs less than 17.90 MB and 100× less than
1.79 MB **including** new offline material and peer links. Compiler-bound
[stage attribution](https://github.com/blairhudson/pllm/blob/main/docs/evidence/prepared-stage-attribution-qwen25-2026-09-29.json)
finds 148.30 MB in MLP stages, but removing *all* of those bodies for free
would still leave 30.67 MB. An MLP-only method cannot meet even the 10× target.
The 39+8 cohort has the same result: 19.77 MB remain against an 11.68 MB
target. A protected region must address both attention and MLP costs, with
numeric fidelity and most body compute still remote.

First screen real **existing pretrained** decoders with immutable source,
complete model-neutral semantic schedules and disjoint public calibration and
held-out/confirmation prompts; no training or model-family execution branches.
The [six-source screen](https://github.com/blairhudson/pllm/blob/main/docs/evidence/pretrained-bottleneck-screen-2026-09-29.json)
found the narrowest sampled hidden state in SmolLM2-135M. A separate real
39+32 W8A8 prepared response completed all 120 remote stages with **88.40 MB**
covered all-link and **55.68 MB** online bodies, compared with Qwen's 178.97 MB
and 113.55 MB in a separate matched-token-count workload. A 12-prompt local
clear-kernel prefill check matched SmolLM's *own* float32 top token 11/12
times; this is not a cross-model task-quality comparison, W8A8 decode parity,
 or a full-wire result. A separate fresh-client-bundle-cache cold cohort records
 120.08 MB covered bodies and 23.48 s median aggregate CPU over two samples,
 excluding upstream source distribution. In an *offline float32 oracle that
 still computes the original MLP*, rank-128 cuts at all 30 layers matched
 4/12 and 6/12 held-out/confirmation prefill selections and 3/12 same-token
 decode on each
cohort. Three cut layers do better but cannot eliminate the other remote
stages. The public prepared transport works for this checkpoint, but no
representative generation-quality or protected share-resident claim follows;
different model/token cohorts require their own matched controls.

**Admission rule:** build one bounded two-share, share-resident complete layer
only when a frozen checkpoint passes both disjoint held-out prefill/decode
decisions and a plausible whole-decoder all-link/material budget. That layer
must execute exact protected scale conversion, private attention/KV and MLP,
one share per independent worker, one-use issuance and abort burns, with no
intermediate client reconstruction. Then measure it before decoder-scale
issuance. Current candidates have not passed this gate; research references
cannot activate an `Experiment`. Repeated-prefix reuse has measured online
benefits for repeated public workloads, not for new prompts.

## Required gates

Every reimplementation advances through the same visible gates:

```text
source + version
  -> clean-room specification
  -> inspectable reference
  -> source-scope fidelity tests
  -> reusable native component
  -> typed compiler/runtime integration
  -> scoped security review
  -> matched benchmark
  -> documented promotion decision
```

Missing evidence stays missing. Functional tests do not establish privacy;
operator benchmarks do not establish complete-model execution; loopback runs do
not establish WAN performance; an adaptation does not become a reproduction
without source-scope fidelity evidence.
