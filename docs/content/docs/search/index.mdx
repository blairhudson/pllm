---
title: "Search"
description: "Compare compatible system designs against explicit resource, quality, and assurance limits."
---

Search uses component records and evidence instead of importing provider code.
Each candidate combines model coverage, operator support, value formats,
conversions, protocols, preparation, kernels, party placement, and numeric policy.

You can limit memory, CPU, network traffic, disk use, latency, throughput, quality
loss, trust assumptions, and evidence maturity. Tradeoffs remain visible; PLLM
does not declare one plan best for every deployment.

Finding a candidate is not proof that it works. A selected plan must compile, run
in its stated environment, and produce matching benchmark and assurance records.

## Python SDK example

```python
from pllm.components import list_components

candidates = [item.to_dict() for item in list_components()]
print([item["component"] for item in candidates])
```

This discovers candidate metadata only. No public SDK search executor is currently available.
