title: "Run your first prepared request"
description: "Start inference and preparation, seal an inventory, and generate locally."
---

This quickstart runs every role on one loopback host. Use a local public Hugging
Face snapshot so checkpoint contents and revision are explicit.

## 1. Install

Use Python 3.11, 3.12, or 3.13 and
[UV](https://docs.astral.sh/uv/getting-started/installation/):

```bash
uv venv --python 3.13
source .venv/bin/activate
uv pip install pllm
pllm --version
```

The published wheel includes `pllm._native`; the current public path does not
need TenSEAL or a Rust toolchain at runtime.

## 2. Set local inputs

Make these values available to the inference, preparation, and client terminals.
All three credentials must differ:

```bash
export PLLM_MODEL_SOURCE="$(pwd)/models/checkpoint"
export PLLM_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export PLLM_PREPARATION_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export PLLM_PROVIDER_PUSH_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
```

`PLLM_MODEL_SOURCE` must contain supported config, tokenizer, and Safetensors
files. These shell names are convenient for this guide; explicit flags below make
each process boundary unambiguous.

## 3. Start inference

```bash
pllm serve "$PLLM_MODEL_SOURCE" \
  --weights public \
  --model-id demo-model \
  --api-key "$PLLM_API_KEY" \
  --provider-push-api-key "$PLLM_PROVIDER_PUSH_API_KEY" \
  --local-files-only \
  --compiled-cache-dir .cache/inference \
  --host 127.0.0.1 \
  --port 8000
```

Inference stores prepared corrections and later executes masked transformer-body
stages. It intentionally does not accept plaintext Responses requests for this
model.

## 4. Start trusted preparation

In a second trusted process with the same checkpoint and shell values:

```bash
pllm preparation serve "$PLLM_MODEL_SOURCE" \
  --model-id demo-model \
  --api-key "$PLLM_PREPARATION_API_KEY" \
  --inference-url http://127.0.0.1:8000 \
  --push-api-key "$PLLM_PROVIDER_PUSH_API_KEY" \
  --local-files-only \
  --compiled-cache-dir .cache/preparation \
  --host 127.0.0.1 \
  --port 8001
```

Preparation is public-weight-only. It receives root seeds before chat, computes
`W*r-s`, pushes corrections to inference's fixed endpoint, waits for acceptance
acknowledgements, and must erase expanded masks. Self-host it unless another
operator is trusted to follow that protocol and not collude with inference.

## 5. Configure and chat

```bash
umask 077
pllm configure \
  --server http://127.0.0.1:8000 \
  --api-key "$PLLM_API_KEY" \
  --preparation-url http://127.0.0.1:8001 \
  --preparation-api-key "$PLLM_PREPARATION_API_KEY" \
  --model demo-model
pllm chat
```

The chat CLI prepares an inventory before showing the prompt. For each response it
calculates the row requirement, refills if needed while idle, reserves the full
range, and then contacts inference only. Prompt rows use compact stage batches;
decode reuses a persistent connection. The default inventory minimum is 64 rows
per stage (`PLLM_PREPARED_INVENTORY_ROWS`).

## 6. Use Python directly

```python
from pllm import OpenAI

prompt = "Explain why preparation is offline."
maximum = 64

with OpenAI() as client:
    response = client.responses.create(
        input=prompt,
        max_output_tokens=maximum,
    )
    print(response.output_text)
```

The SDK calculates the exact row requirement and prepares missing inventory before
it opens the online response. It may also prepare a spare under the default
idle-refill policy. Keep the client open to reuse unreserved rows.

## Verify the boundary

Before `READY`, preparation sees bound metadata and stage seed batches; inference
sees authorizations and corrections. Online, inference sees tickets, masked
inputs, stage metadata, timing, and approximate lengths. Neither service receives
plaintext or activation scales on the documented path, but privacy depends on
honest execution and non-collusion. [Read the complete limits](/docs/security).

For remote evaluation, inference and preparation must use distinct HTTPS origins.
Tune client HTTP timeout, preparation push timeout, provider inventory expiry, and
proxy WebSocket idle timeout independently; see [deployment](/docs/deployment/overview).
