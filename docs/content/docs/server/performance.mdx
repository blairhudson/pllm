## Measure the actual lifecycle

Record at least four phases separately:

| Phase | Work included |
| --- | --- |
| Model and bundle load | Checkpoint resolution, quantization, compiled cache, public boundary bundle transfer/verification |
| Offline inventory | Authorization, seed upload, `W*r-s`, correction push/ACK, seal to `READY` |
| Prompt prefill | Local token lookup, compact multi-row remote stages, local nonlinear work, final-row local head |
| Decode | Persistent client-to-inference stage exchanges, local state/head/sampling, stream delivery |

A warm response using existing READY rows is not cold-start throughput. A matrix
kernel call is not a token. Report prompt length, output limit and actual tokens,
model revision, quantization, ring distribution, hardware, thread count, transport,
and whether public boundary matrices were already cached.

## Current online shape

Each dependent remote stage still incurs client-to-inference latency. Public
preparation removes the second service from online execution; it does not make
dependent transformer stages parallel.

Prefill reduces framing and request overhead by packing all prompt-row tickets and
masked values into one stage request. Decode retains one authenticated WebSocket
for single-row stages. Reverse proxies should therefore optimize large bounded
binary HTTP requests and long-lived low-volume decode connections differently.

## Inventory capacity

`PLLM_PREPARED_INVENTORY_ROWS` controls minimum rows per prepared stage batch. A
response reserves prompt rows plus up to `max_output_tokens - 1` decode rows. Track
capacity, available, reserved, consumed, and burned rows. Large batches reduce
refill frequency but increase preparation time, correction memory, and discard on
restart or idle expiry. Early stop burns only the unused portion of that response's
reservation, not all unreserved inventory.

Approximate inference correction storage from:

```text
inventory rows * sum(remote stage output widths * stage ring bytes)
```

Then add framing, indexes, concurrent inventories, and process overhead. Tune
`--rendezvous-capacity` and `--rendezvous-max-bytes` together; defaults are bounds,
not a promise that every model and batch fits.

## Timeouts

- Client `PLLM_TIMEOUT` bounds HTTP bundle, preparation, and explicit HTTP-mode
  stage operations.
- Persistent decode uses a fixed 30-second WebSocket connect timeout and currently
  no per-receive `PLLM_TIMEOUT` deadline.
- Preparation `--push-timeout` bounds correction connection/send/ACK work.
- Inference `--rendezvous-timeout` bounds unmatched non-preloaded entries; it does
  not retain READY inventory.
- Inference `--prepared-session-idle` controls memory-only inventory expiry.
- Proxy HTTP timeouts must cover compact prefill; decode WebSocket idle timeout
  must exceed legitimate gaps between online stages.

Closing an idle correction WebSocket is recoverable for a later independent
inventory. Closing decode terminates that execution and burns unused reserved
rows. Increase each timeout only after identifying which boundary expired.

## Threads and batching

```bash
pllm serve "$PLLM_MODEL_SOURCE" \
  --weights public \
  --provider-push-api-key "$PLLM_PROVIDER_PUSH_API_KEY" \
  --max-batch-size 16 \
  --max-wait-ms 0.5 \
  --engine-threads 4
```

These are experiment inputs, not recommended universal values. Other sessions can
fill provider batches, but one conversation's dependent stages remain serial.
Measure single-response latency separately from aggregate throughput. Compare one
thread against larger persistent pools on real stage shapes.

## Run the current dashboard

```bash
pllm benchmark dashboard
```

The loopback dashboard starts real client, preparation, and inference roles using
Qwen2.5-0.5B-Instruct by default. It reports observed TTFT, generation rate,
process use, protocol bytes, and inventory state. It persists sanitized run records
for model/context comparison by default; use `--history-db :memory:` for an
ephemeral session. Use `--tiny` only for a quick random-weight transport smoke
test. No number is embedded here because results depend on the executed revision,
checkpoint, hardware, and run state.

See the [dashboard guide](/docs/reference/dashboard) for metric definitions and
limitations.

## Keep private values local

Never send activation scales to simplify provider dequantization. They are not
needed by the integer operation and can fingerprint private activations. OTEL
attributes must not contain prompts or activation payloads. Protocol byte metrics
cover application payloads and PLLM envelopes, not all WebSocket, TLS, or IP
framing; state that scope when reporting bandwidth.
