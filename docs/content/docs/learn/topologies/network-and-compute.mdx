---
title: "Network and compute"
description: "Measure client and all-link bytes without moving uncounted work between roles."
---

Network has at least two useful objectives: bytes crossing the client boundary
and bytes sent across **all** directed links. Count each transmission once,
including peer traffic, offline material, retries, initial model bundles and
attestation. Report cold and warm runs separately, and distinguish prefill
from decode. Fewer client round trips need not mean less total network.

The **client-only** baseline keeps model weights and every operator on the
client. It has no online provider messages and computes each body matrix once.
Cold acquisition of the checkpoint can still require a large download; the
client must retain its weights on disk and hold its quantized working set in
memory. Its prompt privacy needs no remote non-collusion or TEE assumption.

The compute comparator uses two **online** inference workers: the
client splits each integer stage input into fresh additive shares, each server
performs one matching matrix operation, and the client reconstructs before its
local operators. Both matrix operations, client work and any setup count. A
candidate can optimize client bytes, total bytes, or both, while its compute
constraint can cover online work or the full response with honestly amortized
preprocessing. CPU and GPU work need measured, hardware-matched accounting;
adding unlike resource units into one unexplained score is not a comparison.

The [client-only, two-worker and prepared options](/sdk/topologies/options/)
are selectable `Experiment` compositions. The ordinary gateway and
[`benchmark run`](/cli/benchmarking/) use the same native semantic schedule
and runtime driver. In the two-worker graph, separate authenticated processes
re-lower and check the compiled plan, body and stage commitments. The client
gives each a fresh stage share. A checked tiny Qwen2/Qwen3 prefill-to-decode
session matches the masked integer stage path's logits and selected tokens;
the W8A8 client-owned path likewise matches the prepared stage results. This
is bounded execution evidence, not independently operated provider privacy.

A three-Experiment tiny Qwen2 benchmark regression binds **one W8A8 body
fingerprint** and matching input/output token counts across client-only,
two-worker and prepared runs. The role-graph ledger records zero provider-body
bytes for client-only, per-worker stage/setup/teardown application bodies for
the two-worker path, and prepared startup and per-run bodies separately. It
also records run-window CPU for the client and both offset workers when
authenticated samples exist. The prepared path's generated selections are
**not** compared, so matching body and counts are not a model-quality proof.
Unmeasured HTTP/TLS frames, checkpoint distribution, cold setup CPU and
incomplete control traffic prevent a total-network winner or full-response
compute-cap finding. Two loopback workers share one operator and fail the
independent-operator privacy condition.

Reproduce the comparison against the same public Qwen checkpoint with the
[three checked-in Experiments](/cli/benchmarking/). For a cost-free inspection,
add `--dry-run` to the command. For a bounded generated-checkpoint regression,
the test suite builds one tiny checkpoint and executes the same
`run_loopback_benchmark` driver on all three Experiments.

Gemma E2B's pinned W8A8 client bundle alone
measures 2,790,944,732 bytes, so cold-start traffic cannot be hidden inside
warm-token results. Search over new topology choices and per-edge objective
selection remain planned. The [existing benchmark](/cli/benchmarking/) selects
all three CPU topologies but does not rank unqualified network/compute
objectives or establish deployed privacy.

It now records a partial **per-link stage-body ledger** for the current
prepared graph. One checked, single-host `benchmark run --tiny` response with
one output token counted 86,913 serialized body bytes on online client links
and 140,020 across all covered links, including a 51,968-byte offline
Preparation-to-Inference correction push. That run's client bundle was fetched
before its capture window; its zero recorded cold-bundle delta is **not** zero
cold traffic. HTTP/TLS framing, control and acknowledgment traffic, complete
client work, and provider setup are not measured in these figures, and the
generated checkpoint differs from the matched three-topology regression above.
