---
title: "Network and compute"
description: "Measure client and all-link bytes without moving uncounted work between roles."
---

Network has at least two useful objectives: bytes crossing the client boundary
and bytes sent across **all** directed links. Count each transmission once,
including peer traffic, offline material, retries, initial model bundles and
attestation. Report cold and warm runs separately, and distinguish prefill
from decode. Fewer client round trips need not mean less total network.

The proposed compute comparator is two **online** inference servers: the
client splits each integer stage input into fresh additive shares, each server
performs one matching matrix operation, and the client reconstructs before its
local operators. Both matrix operations, client work and any setup count. A
candidate can optimize client bytes, total bytes, or both, while its compute
constraint can cover online work or the full response with honestly amortized
preprocessing. CPU and GPU work need measured, hardware-matched accounting;
adding unlike resource units into one unexplained score is not a comparison.

A bounded in-process reference exercises that split through the same compiled
tiny Qwen2/Qwen3 prefill/decode path. It records two logical workers' serialized
stage bodies and integer matrix operations. Both workers still run in one
process; these are **not** deployed network bytes, independent operators or
full-response aggregate compute measurements.

The reproducible tiny diagnostic runs the exact same W8A8 checkpoint and
prefill/decode token cohort through clear native stages and two additive-share
stage calls. Each one-layer Qwen2/Qwen3 run has eight remote stages and 55,296
integer multiply-accumulates across both logical workers. Three local runs per
adapter selected identical tokens, with no logit difference from clear W8A8;
the two-worker serialization totaled roughly 14.7 KB per run. These are
**stage-body** bytes, not wire bytes or full-model evidence. To reproduce the
Qwen2 diagnostic from the repository root:

```bash
uv run --frozen python scripts/benchmark_offset_reference.py --model-type qwen2 --repeats 3
```

The analogous checked Qwen3 run uses `--model-type qwen3`. Reports include
only plan identifiers, counts and aggregate values, not prompts or token IDs.

Current public prepared inference instead uses one online provider plus
offline correction generation. It already has different client traffic and
setup work from that comparator. Gemma E2B's pinned W8A8 client bundle alone
measures 2,790,944,732 bytes, so cold-start traffic cannot be hidden inside
warm-token results. Search over new topology choices and per-edge objective
selection remain planned; the [existing benchmark](/cli/benchmarking/) does
not claim to perform this comparison yet.
