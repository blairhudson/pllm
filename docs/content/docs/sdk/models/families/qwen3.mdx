---
title: "Dense Qwen3"
description: "Dense Qwen3 lowering with explicit head width and Q/K normalization."
---

`pllm.qwen3.v1` extends dense lowering with explicit `head_dim`, per-head Q/K RMS normalization, and configuration-controlled attention bias. Attention projection width is `num_attention_heads * head_dim`; it is not assumed equal to hidden width.

The checked [Qwen3-0.6B source](https://huggingface.co/Qwen/Qwen3-0.6B/tree/c1899de289a04d12100db370d81485cdf75e47ca) is pinned to revision `c1899de289a04d12100db370d81485cdf75e47ca`, raw configuration SHA-256 `660db3b73d788119c04535e48cf9be5f55bc3100841a718637ae695b442f27dd`. Its config omits `layer_types`; full attention is admitted only when all declared attention/window settings are consistent with dense attention. The earlier `ricdomolm/mini-coder-4b` configuration fixture also passes semantic lowering. These checks establish configuration and schedule validity, not real-checkpoint execution or quality.

## Python SDK example

```python
from pathlib import Path

from pllm import lower_model

fixture = Path("crates/pllm-models/tests/fixtures/Qwen3-0.6B-c1899de-config.json")
plan = lower_model(fixture.read_bytes(), batch=1, max_input_tokens=16, max_new_tokens=4)
operations = {operation["id"]: operation for operation in plan.prefill["operations"]}
assert operations["layer.0.q_norm"]["operator"] == "rms_norm"
assert operations["layer.0.rope_q"]["output_shape"][-1] == 128
```

API: [Python SDK objects and signatures](/sdk/reference/python/pllm/#objects-and-signatures)

Run this example from a PLLM source checkout; package installations do not include
the pinned Qwen3 fixture. This does not execute the model.
