title: "Dense Qwen3"
description: "Dense Qwen3 lowering with explicit head width and Q/K normalization."
---

`pllm.qwen3.v1` extends dense lowering with explicit `head_dim`, per-head Q/K RMS normalization, and configuration-controlled attention bias. Attention projection width is `num_attention_heads * head_dim`; it is not assumed equal to hidden width.

The checked [Qwen3-0.6B source](https://huggingface.co/Qwen/Qwen3-0.6B/tree/c1899de289a04d12100db370d81485cdf75e47ca) is pinned to revision `c1899de289a04d12100db370d81485cdf75e47ca`, raw configuration SHA-256 `660db3b73d788119c04535e48cf9be5f55bc3100841a718637ae695b442f27dd`. Its config omits `layer_types`; full attention is admitted only when all declared attention/window settings are consistent with dense attention. The earlier `ricdomolm/mini-coder-4b` configuration fixture also passes semantic lowering.

The pinned real checkpoint imports and executes 114 compiled baseline stages through prefill and decode in a local clear-kernel test. Tiny Qwen3 also runs that semantic schedule through the prepared two-role loopback path. This tests **binding, complete scheduling and tiny transport**, not generation quality or a real-checkpoint provider deployment. In a [small same-token reference probe](https://github.com/blairhudson/pllm/blob/main/docs/evidence/qwen3-0.6b-reference-probe-2026-09-24.json), W4A4 selected a different next token from FP32 Transformers on both prompts. W8A8 (the local-role default) matched one five-token prompt through decode, but failed the short `Hello` prefill. With the W8 token/head boundary and unquantized float32 body projections, `Hello` matched the reference top token (0.38 maximum logit difference): accumulated activation **and** weight quantization error is the immediate quality gate. The float32 body is a local diagnostic, not a private execution choice. Wider prompts, model quality, real-checkpoint provider transport and matched cost remain unmeasured.

## Python SDK example

```python
from pathlib import Path

from pllm import lower_model

fixture = Path("crates/pllm-models/tests/fixtures/Qwen3-0.6B-c1899de-config.json")
plan = lower_model(fixture.read_bytes(), batch=1, max_input_tokens=16, max_new_tokens=4)
operations = {operation["id"]: operation for operation in plan.prefill["operations"]}
assert operations["layer.0.q_norm"]["operator"] == "rms_norm"
assert operations["layer.0.rope_q"]["output_shape"][-1] == 128
```

API: [Python SDK objects and signatures](/sdk/reference/python/pllm/#objects-and-signatures)

Run this example from a PLLM source checkout; package installations do not include
the pinned Qwen3 fixture. This does not execute the model.
