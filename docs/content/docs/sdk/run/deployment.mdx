---
title: "Deployment"
description: "Learn how to assign PLLM roles to authenticated services without changing privacy assumptions."
---

A deployment assigns each protocol role to a process and operator. An
`Experiment.deployment` selects local execution or an authenticated network.
A separate, digest-bound `RoleDeployment` document can **inspect** operator IDs, HTTPS
origins and optional TEE policies against a role graph, but does not change
that live Experiment, authenticate an operator or authorize new roles.
Execution must still account for endpoints, distinct credentials, capacity,
expiration, observability, shutdown and trust boundaries.
Review [privacy and threat models](/learn/concepts/privacy-and-threat-models/) before
changing that placement.

The current prepared client must keep plaintext prompts, masks, private scales,
model state, and decoding. Client-to-inference, client-to-preparation, and
preparation-to-inference connections use different credentials. Changing the URL
of an ordinary model API does not make its unmodified SDK private.

A loopback [`pllm benchmark run`](/cli/reference/benchmark/run/) checks that the
services work together on one machine. It does not show that production operators
are independent. Deployment assurance must refer to the exact plan and environment
being evaluated. The [serving integration guide](/learn/integrations/local-gateway/)
lists the current gateway and provider-role lifecycle commands.

## Python SDK example

### Automatic network requests

Configure the installed network and Experiment once in `PLLM_CONFIG` (or the
default `~/.config/pllm/config.toml`). Relative paths resolve beside that TOML file:

```toml
[client]
network = "network.json"
experiment = "experiment.json"
```

Provider credentials use the environment references in the network declaration.
Ordinary calls own discovery, native selection, fresh admission, preparation and
release:

```python
from pllm import OpenAI

with OpenAI() as client:
    response = client.responses.create(input="Hi", max_output_tokens=2, temperature=0)
    print(response.output_text)
    decision = client.planning(response.id)
    assert decision.status == "feasible"
```

`AsyncOpenAI()` uses the same lifecycle. Closing a stream, cancelling an async
request or closing the client drains owned work and retires leases. Response
records and immutable planning explanations each have a 4 MiB / 64-entry bound.
An explicit `OpenAI(network=network, experiment=experiment, planning=policy)`
overrides configured selection inputs. `PlanningPolicy()` supplies bounded
defaults; `[client.planning]` accepts the same optional policy fields.

An optional `[client] performance_prior = "performance.json"` (or
`PLLM_PERFORMANCE_PRIOR`) loads a compact
[`PlanningPrior`](/sdk/deployment/#fast-decisions-from-prior-measurements) compiled
from matched network benchmarks. `OpenAI(..., performance_prior=prior)` accepts
the same record directly. Matching complete evidence ranks historical TTFT and
decode cost before geometric ties, with fresh resource checks and leases on every
request. Repeated decisions reuse bounded immutable planning work; selection does
not benchmark the current prompt. Stale, changed or missing evidence falls back
to the ordinary geometry objectives.

`pllm gateway` consumes the same configured deployment. Explicit
`pllm gateway --network network.json --experiment experiment.json` selects it
without a saved plan; `--planning-policy policy.json` optionally overrides policy.
Advanced callers can still pass `execution=lease`, `--plan` or `--request`.

The SDK observes process RSS, post-reserve host RAM and other active client
reservations before selecting and opening each attempt. On Linux, visible cgroup
v1/v2 memory ceilings and ancestor usage further constrain headroom. No swap or
reclaimable-cache credit is assumed. Complete native allocation-owner estimates
include loading, masks, attention, KV, full outputs and selected MLP intermediates,
with the benchmark's 25% margin. These are conservative admission estimates, not
an OS-enforced peak-RSS guarantee.

Hosts can advertise up to 32 compatible installed Pipelines through
`PartySpec(alternatives=(... ,))`. The SDK considers only installed, compatible
combinations across MLP tiling, client paging, raw/compressed/artifact delivery,
artifact batching, preparation inventory sizing/windowing, exact request/output
codecs, and supported kernel/Preparation implementations. Source, precision,
verifier, topology, placement, reuse permissions and trusted artifacts remain bound
to the configured experiment. A tighter RAM budget can select paging or
`MlpPrefillTiling`; insufficient headroom rejects before issuing material.
Defaults prefer fewer dependent prefill exchanges, then smaller online arithmetic
bodies, preprocessing bodies and client weights. These estimates omit framing,
public delivery and CPU; they do not predict complete request latency.
Pin the configured Pipeline or set a process budget in
the same settings file:

```toml
[client.planning]
max_client_peak_memory_bytes = 1073741824
max_client_native_threads = 2
candidate_selection = "pinned"
```

Omit `candidate_selection` to keep automatic installed-choice selection. An
explicit `PlanningPolicy(max_client_peak_memory_bytes=1 << 30)` supplies the same
limit through the SDK. A full `PlanningPolicy` also sets its own ranking; add
`objectives=("prefill_dependent_exchanges", "online_all_link_body_bytes",
"preprocessing_all_link_body_bytes", "client_weight_bytes")` to retain the
automatic client's ranking. Both declared limits and observed headroom must hold.
Policy, observations and rejected choices remain client-local; providers receive
the exact selected role admission contract and independently recheck it.

`max_client_native_threads` accepts 1–32 and caps client-owned native matrix
executors, including paged imports and cold/warm bundle-cache reads. A lower
selected kernel count remains lower. Client-only candidates whose
source loader requires more native workers reject during planning. This is a
per-executor limit; it does not cap Python/BLAS threads, concurrent requests,
provider workers, GPU work or whole-request CPU time.

One host shares its installed engine across lease-local adapters. Its alternatives
must retain native kernels, prepared output-residue layouts and, on a Preparation
host, Preparation storage/kernel choices. Separately installed compatible hosts
can advertise those other choices. The selected adapter binds its own wire and
inventory contract; a provider never silently changes engine ownership.

`optimization_space(component_choices=...)` builds bounded interacting component
axes for explicit planning or provider provisioning; see [search](/sdk/evaluate/search/).
Ordinary application calls need no candidate construction. Public tokenizer/prefix
artifacts and private prefix reuse stay explicitly configured. Unknown required
CPU/GPU costs reject; compatibility alone cannot earn a speed ranking.

Planning explanations retain dependent prefill/decode exchange counts and separate
directed-link delay estimates. Missing link observations remain unknown. Whole-
request CPU and cross-workload TTFT/decode predictions need further phase evidence;
configured priors retain their measured workload/lifecycle scope. Exchange counts
do not certify performance. A fresh lease does not retain a
previous response's private decoder state.

The checked example is
[`examples/automatic_client.py`](https://github.com/blairhudson/pllm/blob/main/examples/automatic_client.py).
Prepared Inference/Preparation and two-offset HTTP roles are admitted; operator
independence remains a deployment claim requiring separate evidence.

### Inspect a role declaration

```python
from pllm import Experiment
from pllm.deployment import Deployment, RoleDeployment

deployment = Deployment.local(root=".pllm/local")
assert deployment.to_spec() == {"kind": "local", "root": ".pllm/local"}
experiment = Experiment.from_file("examples/prepared-topology.yaml")
graph = experiment.resolve().role_graph
declaration = RoleDeployment.from_file("examples/prepared-role-deployment.json")
assessment = declaration.assess(graph)
assert assessment.declared_separation_violations == ()
assert not assessment.operator_independence_verified
assert not assessment.runtime_admission_supported
```

API: [`pllm.deployment`](/sdk/reference/python/pllm/deployment/#objects-and-signatures)

This checks a declaration only. The same Experiment still runs locally and
does not satisfy its Preparation–Inference non-collusion assumption. This separate
declaration does not authorize live remote roles or TEE attestation. Read
[role trust](/learn/topologies/roles-and-trust/) and
[TEE boundaries](/learn/topologies/trusted-execution/) before treating an
operator label or policy fingerprint as security evidence.
