---
title: "Deployment"
description: "Learn how to assign PLLM roles to authenticated services without changing privacy assumptions."
---

A deployment assigns each protocol role to a process and operator. An
`Experiment.deployment` selects local execution or an authenticated network.
A separate, digest-bound `RoleDeployment` document can **inspect** operator IDs, HTTPS
origins and optional TEE policies against a role graph, but does not change
that live Experiment, authenticate an operator or authorize new roles.
Execution must still account for endpoints, distinct credentials, capacity,
expiration, observability, shutdown and trust boundaries.
Review [privacy and threat models](/learn/concepts/privacy-and-threat-models/) before
changing that placement.

The current prepared client must keep plaintext prompts, masks, private scales,
model state, and decoding. Client-to-inference, client-to-preparation, and
preparation-to-inference connections use different credentials. Changing the URL
of an ordinary model API does not make its unmodified SDK private.

A loopback [`pllm benchmark run`](/cli/reference/benchmark/run/) checks that the
services work together on one machine. It does not show that production operators
are independent. Deployment assurance must refer to the exact plan and environment
being evaluated. The [serving integration guide](/learn/integrations/local-gateway/)
lists the current gateway and provider-role lifecycle commands.

## Python SDK example

### Automatic network requests

Configure the installed network and Experiment once in `PLLM_CONFIG` (or the
default `~/.config/pllm/config.toml`). Relative paths resolve beside that TOML file:

```toml
[client]
network = "network.json"
experiment = "experiment.json"
```

Provider credentials use the environment references in the network declaration.
Ordinary calls own discovery, native selection, fresh admission, preparation and
release:

```python
from pllm import OpenAI

with OpenAI() as client:
    response = client.responses.create(input="Hi", max_output_tokens=2, temperature=0)
    print(response.output_text)
    decision = client.planning(response.id)
    assert decision.status == "feasible"
```

`AsyncOpenAI()` uses the same lifecycle. Closing a stream, cancelling an async
request or closing the client drains owned work and retires leases. Response
records and immutable planning explanations each have a 4 MiB / 64-entry bound.
An explicit `OpenAI(network=network, experiment=experiment, planning=policy)`
overrides configured selection inputs. `PlanningPolicy()` supplies bounded
defaults; `[client.planning]` accepts the same optional policy fields.

`pllm gateway` consumes the same configured deployment. Explicit
`pllm gateway --network network.json --experiment experiment.json` selects it
without a saved plan; `--planning-policy policy.json` optionally overrides policy.
Advanced callers can still pass `execution=lease`, `--plan` or `--request`.

This first slice chooses hosts for the installed Pipeline and bounded workload.
Required costs that lack evidence still reject, including complete client CPU
and peak-memory requirements. Automatic full-versus-tiled candidate generation
and phase-aware TTFT/decode-TPS optimization are subsequent slices. A fresh lease
does not retain a previous response's private decoder state.

The checked example is
[`examples/automatic_client.py`](https://github.com/blairhudson/pllm/blob/main/examples/automatic_client.py).
Prepared Inference/Preparation and two-offset HTTP roles are admitted; operator
independence remains a deployment claim requiring separate evidence.

### Inspect a role declaration

```python
from pllm import Experiment
from pllm.deployment import Deployment, RoleDeployment

deployment = Deployment.local(root=".pllm/local")
assert deployment.to_spec() == {"kind": "local", "root": ".pllm/local"}
experiment = Experiment.from_file("examples/prepared-topology.yaml")
graph = experiment.resolve().role_graph
declaration = RoleDeployment.from_file("examples/prepared-role-deployment.json")
assessment = declaration.assess(graph)
assert assessment.declared_separation_violations == ()
assert not assessment.operator_independence_verified
assert not assessment.runtime_admission_supported
```

API: [`pllm.deployment`](/sdk/reference/python/pllm/deployment/#objects-and-signatures)

This checks a declaration only. The same Experiment still runs locally and
does not satisfy its Preparation–Inference non-collusion assumption. This separate
declaration does not authorize live remote roles or TEE attestation. Read
[role trust](/learn/topologies/roles-and-trust/) and
[TEE boundaries](/learn/topologies/trusted-execution/) before treating an
operator label or policy fingerprint as security evidence.
