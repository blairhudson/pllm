description: "Separate installed role graphs from paper-linked research topologies."

The public masked-linear composition currently resolves to Client, offline
Preparation and online Inference. You can **select the same installed graph
explicitly** in the `topology` component slot: its composition and execution
digests change, and the native compiler and provider bind that choice before
prepared inference. Existing Experiments without the slot keep their original
digests. Optional Freivalds verification adds an offline Preparation-to-Client
projection channel. Installed proprietary compositions resolve to Client and
one provider under separate protocol contracts.

Choose `ClientOnlyCpu` for a **client-only** Experiment. Its `pllm/client-only/v1`
role graph has one client and no inference or preparation channels; the same
compiler-bound semantic decoder loads all public weights locally. It runs through
`pllm.Client`, `pllm gateway --local --experiment` and `pllm benchmark run
--experiment` without provider children. W8A8 is the default; W4A4 and other
numeric choices need their own quality checks. The benchmark records zero
provider-graph bytes and client run-window CPU when telemetry is available.
Checkpoint download, disk activity, client peak memory and the application's
own HTTP traffic are not counted as zero; they are outside that network scope.

The two-online-offset comparator has a bounded **in-process numeric reference**:
two separately loaded native kernels run a complete tiny Qwen2/Qwen3 compiled
prefill/decode and count per-worker serialized stage bodies and integer work.
An opt-in [loopback comparison](/learn/topologies/network-and-compute/) now
runs that compiled plan with two authenticated worker processes and accounts
for stage plus setup/teardown HTTP application bodies. Both processes share one
operator. Neither reference is an independently operated or selectable
topology; the loopback diagnostic measures online per-role process CPU but
not cold-start CPU, complete network or an admitted compute cap. Resident
two/three-party MPC, dealer/FSS, TEE-only and
TEE-plus-accelerator arrangements still require their own complete compiler,
transport and privacy-admission contracts. They cannot be
selected by adding an unknown pipeline component, editing a graph document or
changing a provider URL. Existing paper-linked pending classes remain
non-executable.

## Python SDK example

```python
from pllm import Experiment, Pipeline
from pllm.profiles import ClientOnlyCpu
from pllm.roles import Channel, PreparedProviderRoles

original = Experiment.from_file("examples/pllm.yaml")
selected = Pipeline(
    model=original.pipeline.model,
    components={**original.pipeline.components, "topology": PreparedProviderRoles()},
)
experiment = Experiment(
    name=original.name,
    pipeline=selected,
    deployment=original.deployment,
    budget=original.budget,
)
graph = experiment.resolve().role_graph
assert graph is not None
assert Channel("client", "inference", "online", "masked_stage_input") in graph.channels
assert ("inference", "preparation") in graph.separate_operators
assert experiment.pipeline.digest() != original.pipeline.digest()
assert Experiment.from_spec(experiment.to_spec()).resolve().composition_digest == selected.digest()
local = Experiment(
    name="client-only-qwen",
    pipeline=ClientOnlyCpu(original.pipeline.model),
    deployment=original.deployment,
    budget=original.budget,
)
single = local.resolve().role_graph
assert single is not None and len(single.roles) == 1 and single.channels == ()
assert single.roles[0].id == "client"
assert local.resolve().composition_digest != experiment.resolve().composition_digest
```

Run from the repository root. Inspect [components and runnable inference](/sdk/inference/)
separately from [research papers](/research/papers/).

API: [pllm.profiles](/sdk/reference/python/pllm/profiles/#objects-and-signatures),
[pllm.roles](/sdk/reference/python/pllm/roles/#objects-and-signatures).
