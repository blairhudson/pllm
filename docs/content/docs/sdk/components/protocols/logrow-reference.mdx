---
title: "Bounded LogRow lookup reference"
description: "Understand the private 9-bit table lookup reference, full material cost, and why it is not a selectable inference method."
---

PLLM's native `pllm-garble::logrow` reference evaluates a private table lookup
without telling its evaluator which **unmasked** row was selected. For a fitted
[Compact Q7 SiLU profile](/sdk/components/nonlinear/compact-q7-reference/),
the trusted garbler builds a 512-row, 9-bit table (257 valid signed-Q7 inputs
and unused padded rows). The client supplies one-use garbled input labels and
decodes the returned signed Q7 value. The evaluator sees a random-looking
masked row index, protected one-hot labels, masked table bits and output labels;
it does not receive the client's original input, the row mask, or the plaintext
table. The implementation uses the two-row one-hot setup from
[Heath and Kolesnikov's *One Hot Garbling*](https://eprint.iacr.org/2022/798),
not the more efficient one-row setup in the LogRow paper.

The Rust compiler binds a fitted Q7 lookup either to **one SiLU element** or to
the **entire bounded semantic SiLU tensor** for one prefill/decode phase. Both
bind the decoder plan, operation, profile, implementation source, policy and
fresh circuit identity; the scalar path additionally binds its tensor position.
The tensor path preflights every row and the full evaluator-body budget before
issuing material, revalidates the whole context before evaluation, and burns
the entire one-use tensor on invalid input. The experimental hard ceiling is
64 MiB per tensor. This is not yet a session-wide scheduler or model execution.

This is an **in-process Rust reference**, not a deployment boundary: it has no
transport, independent provider, Python execution API, security review, or
whole-decoder composition. The Python symbol
[`LogRowGarbledLookup`](/sdk/reference/python/pllm/protocols/#logrowgarbledlookup)
remains a pending declaration and raises `NotYetImplementedError`; it cannot
be added to an `Experiment` or selected in search. **No public Python API
executes this reference.** Use the supported
[masked-linear inference composition](/sdk/inference/masked-linear/) for an
actual private response.

## What is measured

| Resource | Current 9-bit fitted Q7 reference |
| --- | --- |
| Evaluator material | **2,144 bytes per scalar**: 272 one-hot setup bytes, 1,296 random-function row bytes, 576 masked table bytes. A 32-element tensor requires exactly 68,608 body bytes, preflighted before issuance. |
| Input / output labels | Nine 16-byte input labels and nine 16-byte output labels per scalar. These are **additional** to the 2,144-byte material; protocol framing is not included. |
| Prior oracle | The 257-row protected Compact lookup oracle uses 73,728 half-gate ciphertext bytes alone; these counts are **not** matched end-to-end traffic measurements. |
| Memory | Bounded 512-row table and one-hot seed vectors in-process; per-tensor evaluator material is capped at 64 MiB. Peak heap and allocator overhead have **not** been measured. |
| CPU | Full tree preparation, random-function masking, table packing and evaluator XOR/hash work; no controlled wall-time or throughput measurement. |
| Disk | No persistent material is written by the reference; a caller's checkpoint/calibration storage is separate. |
| Network | No network path exists. The 2,144-byte body and 144-byte input/output labels are potential payload terms, **not** observed network traffic. |
| Privacy | A fresh one-use circuit hides the input row and table under the stated garbler/evaluator model. Cryptographic assurance for this PLLM adaptation has not been established. |

Native tests exhaust all 257 signed-Q7 inputs for a fitted profile and check
cross-circuit rejection, output-label tampering, width limits and one-use
consumption. Qwen2 and dense Qwen3 compiler tests exercise complete 16- and
32-element semantic SiLU tensors in decode and prefill, verify material and
element-limit preflight, and reject plan, phase, profile, policy and circuit
mismatches. This establishes bounded tensor parity, not checkpoint quality or
production privacy. The next gates are whole-session admission, a float-to-Q7
numeric bridge, reviewed provider input transfer, a composable protected
decoder operator, complete transport-cost measurement, and matched model
quality/cost evidence. The [research method roadmap](/sdk/components/research-method-roadmap/)
tracks the pending Python component independently of this reference.

<Callout type="info" title="Research citations">

[LogRow](/research/papers/logrow/) contributes the random-function mask that
permits a privately selected row while sending logarithmically many
security-parameter-sized rows **plus the masked table**. The one-hot setup in
this particular reference comes from [One Hot Garbling](https://eprint.iacr.org/2022/798)
(David Heath and Vladimir Kolesnikov, CCS 2021; ePrint 2022/798).

</Callout>
