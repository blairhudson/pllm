title: "Bounded LogRow lookup reference"
description: "Understand the private 9-bit table lookup reference, full material cost, and why it is not a selectable inference method."
---

PLLM's native `pllm-garble::logrow` reference evaluates a private table lookup
without telling its evaluator which **unmasked** row was selected. For a fitted
[Compact Q7 SiLU profile](/sdk/components/nonlinear/compact-q7-reference/),
the trusted garbler builds a 512-row, 9-bit table (257 valid signed-Q7 inputs
and unused padded rows). The client supplies one-use garbled input labels and
decodes the returned signed Q7 value. The evaluator sees a random-looking
masked row index, protected one-hot labels, masked table bits and output labels;
it does not receive the client's original input, the row mask, or the plaintext
table. The implementation uses the two-row one-hot setup from
[Heath and Kolesnikov's *One Hot Garbling*](https://eprint.iacr.org/2022/798),
not the more efficient one-row setup in the LogRow paper.

The Rust compiler binds a fitted Q7 lookup either to **one SiLU element** or to
the **entire bounded semantic SiLU tensor** for one prefill/decode phase. Both
bind the decoder plan, operation, profile, implementation source, policy and
fresh circuit identity; the scalar path additionally binds its tensor position.
The tensor path preflights every row and the full evaluator-body budget before
issuing material, revalidates the whole context before evaluation, and burns
the entire one-use tensor on invalid input. The experimental hard ceiling is
64 MiB per tensor. An offline session can preissue the complete bounded
prefill/decode sequence, enforce order, and burn unused material on failure.

This is an **in-process research reference**, not a deployment boundary: its
Python handle calls native Rust locally and has no transport, independent
provider, security review, or generally supported decoder composition. The component class
[`LogRowGarbledLookup`](/sdk/reference/python/pllm/protocols/#logrowgarbledlookup)
remains a pending declaration and raises `NotYetImplementedError`; it cannot
be added to an `Experiment` or selected in search. Use
[`prepare_logrow_q7_tensor_reference`](/sdk/reference/python/pllm/protocols/#prepare_logrow_q7_tensor_reference)
only for bounded Q7 tensors in local research; use the supported
[masked-linear inference composition](/sdk/inference/masked-linear/) for an
actual private response.

## Python SDK example

This runnable example lowers a tiny **configuration** (no checkpoint or
inference server), selects its semantic SiLU tensor, and evaluates 16 signed
Q7 elements exactly once. Calibration counts are public offline inputs, not
private prompt activations. The little-endian signed-i16 format is explicit.

```python
import struct

from pllm import lower_model
from pllm.nonlinear import fit_compact_silu_q7_reference
from pllm.protocols import (
    estimate_logrow_q7_session_reference,
    prepare_logrow_q7_session_reference,
    prepare_logrow_q7_tensor_reference,
)

config = {
    "model_type": "qwen2", "hidden_size": 8, "intermediate_size": 16,
    "num_hidden_layers": 1, "num_attention_heads": 2, "num_key_value_heads": 1,
    "vocab_size": 32, "max_position_embeddings": 32, "hidden_act": "silu",
    "rms_norm_eps": 1e-6, "rope_theta": 10000.0, "tie_word_embeddings": True,
}
plan = lower_model(config, batch=1, max_input_tokens=2, max_new_tokens=1)
profile = fit_compact_silu_q7_reference(struct.pack("<257I", *([0] * 257)))
session = estimate_logrow_q7_session_reference(
    plan, profile, max_elements=32, max_evaluator_material_bytes=32 * 2144,
    max_decode_steps=1, max_session_evaluator_material_bytes=48 * 2144,
)
assert session.reserved_evaluator_material_bytes == 48 * 2144
operation = next(op["id"] for op in plan.decode["operations"] if op["operator"] == "silu")
material = prepare_logrow_q7_tensor_reference(
    plan, profile, mode="decode", operation_id=operation,
    max_elements=16, max_evaluator_material_bytes=16 * 2144,
)
values = [-128, -64, 0, 32, 128] + [0] * 11
output = material.evaluate(struct.pack("<16h", *values))
assert struct.unpack("<16h", output) == tuple(profile.evaluate(x) for x in values)

# Float32 conversion is explicit and rejects any input outside [-1, 1].
float_material = prepare_logrow_q7_tensor_reference(
    plan, profile, mode="decode", operation_id=operation,
    max_elements=16, max_evaluator_material_bytes=16 * 2144,
)
floats = [-1.0, -0.5, 0.0, 0.5, 1.0] + [0.0] * 11
float_output = float_material.evaluate_float32(struct.pack("<16f", *floats))
assert struct.unpack("<16f", float_output)[2] == 0.0

# An offline session preissues the whole 2-token prefill + 1 decode step.
# Order is semantic: prefill's SiLU tensor, then decode's SiLU tensor.
session_material = prepare_logrow_q7_session_reference(
    plan, profile, max_elements=32, max_evaluator_material_bytes=32 * 2144,
    max_decode_steps=1, max_session_evaluator_material_bytes=48 * 2144,
)
prefill_operation = next(
    op["id"] for op in plan.prefill["operations"] if op["operator"] == "silu"
)
prefill_output = session_material.evaluate_float32(
    "prefill", 0, prefill_operation, struct.pack("<32f", *([0.0] * 32))
)
decode_output = session_material.evaluate_float32(
    "decode", 0, operation, struct.pack("<16f", *([0.0] * 16))
)
assert len(prefill_output) == 128 and len(decode_output) == 64
assert session_material.remaining_tensors == 0
```

API: [`pllm.protocols` objects and signatures](/sdk/reference/python/pllm/protocols/#objects-and-signatures)

The [session estimator](/sdk/reference/python/pllm/protocols/#estimate_logrow_q7_session_reference)
checks the **sum** of prefill bodies and every permitted decode-step body
without creating one-use material. The
[offline session](/sdk/reference/python/pllm/protocols/#prepare_logrow_q7_session_reference)
enforces the same bound before issuing material, consumes tensors in semantic
order, and burns all remaining tensors on failure, abort or drop. The compiled
runtime can use this session through an explicit `research_logrow_material`
argument, binding the selected semantic SiLU operator at each layer and giving
the research run a distinct execution digest. Its `complete` flag stays false
and its scope is `bounded_local_research_reference`: this remains outside
`Pipeline`, `Experiment`, gateway and search selection.
Independent tensor preparation does not require this session gate.

## What is measured

| Resource | Current 9-bit fitted Q7 reference |
| --- | --- |
| Evaluator material | **2,144 bytes per scalar**: 272 one-hot setup bytes, 1,296 random-function row bytes, 576 masked table bytes. A 32-element tensor requires exactly 68,608 body bytes, preflighted before issuance. |
| Whole-response estimate | An admitted tiny two-token prefill plus one decode step needs **102,912 evaluator-body bytes** for one 16-wide SiLU per phase. The estimator rejects total budgets below that amount; this is not peak resident memory or network usage. The experimental per-session limit is 512 MiB. |
| Float32 bridge | Ties-to-even Q7 quantization only within `[-1, 1]`; no clipping or private range/scale disclosure. Input quantization error is at most 1/256. The returned float32 is exactly the decoded Q7 result divided by 128; against continuous SiLU, absolute error is at most `1/256 + (profile.maximum_encoded_error + 0.5)/128` over the admitted domain. Inputs outside it fail and burn the tensor. |
| Input / output labels | Nine 16-byte input labels and nine 16-byte output labels per scalar. These are **additional** to the 2,144-byte material; protocol framing is not included. |
| Prior oracle | The 257-row protected Compact lookup oracle uses 73,728 half-gate ciphertext bytes alone; these counts are **not** matched end-to-end traffic measurements. |
| Memory | Bounded 512-row table and one-hot seed vectors in-process; per-tensor evaluator material is capped at 64 MiB. Peak heap and allocator overhead have **not** been measured. |
| CPU / latency | A retained three-pair **synthetic, in-process** cohort per model recorded LogRow online medians of **693 ms (Qwen2)** and **699 ms (Qwen3)** versus clear local baselines of **72 ms** and **77 ms**; offline issuance took **834 ms** and **840 ms** per response. CPU medians show the same direction. This is slower in the tested setup; no provider throughput or real-model comparison is established. [Inspect exact cohorts and environment](https://github.com/blairhudson/pllm/blob/main/docs/evidence/logrow-local-reference-2026-09-24.json). |
| Disk | No persistent material is written by the reference; a caller's checkpoint/calibration storage is separate. |
| Network | No network path exists. The 2,144-byte body and 144-byte input/output labels are potential payload terms, **not** observed network traffic. |
| Privacy | A fresh one-use circuit hides the input row and table under the stated garbler/evaluator model. Cryptographic assurance for this PLLM adaptation has not been established. |

The matched tiny cohorts used the same public checkpoint and plan within each
pair, two input and two output tokens, and one-use material per response. All
three pairs per model selected identical token sequences; maximum prefill
absolute logit differences were 0.00169 (Qwen2) and 0.00798 (Qwen3). In-process
stage tensor byte counts were the same (**9,984**) for both methods; they are
not network measurements. No peak heap, disk delta or provider traffic was
measured, and real-checkpoint activation ranges remain unsupported.

Native tests exhaust all 257 signed-Q7 inputs for a fitted profile and check
cross-circuit rejection, output-label tampering, width limits and one-use
consumption. Qwen2 and dense Qwen3 compiler tests exercise complete 16- and
32-element semantic SiLU tensors in decode and prefill through Rust and Python,
verify material and element-limit preflight, and reject plan, phase, profile,
policy and circuit mismatches. A separately controlled tiny Qwen2/Qwen3
checkpoint passes full prefill and decode through the opt-in compiled client
when its public gate weights keep activations inside `[-1, 1]`. Even the
ordinary generated tiny checkpoint **fails closed** on out-of-range gates, so
this does not establish general checkpoint quality or production privacy. The
next gates are publicly calibrated support for wider activations, reviewed provider input
transfer, a composable protected
decoder operator, complete transport-cost measurement, and matched model
quality/cost evidence. The [research method roadmap](/sdk/components/research-method-roadmap/)
tracks the pending Python component independently of this reference.

<Callout type="info" title="Research citations">

[LogRow](/research/papers/logrow/) contributes the random-function mask that
permits a privately selected row while sending logarithmically many
security-parameter-sized rows **plus the masked table**. The one-hot setup in
this particular reference comes from [One Hot Garbling](https://eprint.iacr.org/2022/798)
(David Heath and Vladimir Kolesnikov, CCS 2021; ePrint 2022/798).
