title: "Private embedding lookup"
description: "Benchmark bounded encrypted coefficient lookup, signed packed-share conversion and complete local ownership."

`pllm.protocols.PrivateEmbeddingLookup` exposes a bounded, experimental
[FastQuery](/research/papers/fastquery/) component through ordinary operator
benchmarks. Rust packs signed table codes and owns one-use conversion circuits;
SEAL executes encrypted one-hot polynomial products in distinct client/provider
contexts. The provider context contains no client secret key.

## Python SDK example

Install `pllm.run[he]` for the supported TenSEAL/SEAL dependency.

```python
from pllm.metrics import benchmark_operator, replay_operator_benchmark
from pllm.protocols import PrivateEmbeddingLookup

method = PrivateEmbeddingLookup(vocabulary_size=256, precision="mixed_4_3_3",
                               repacking="pack_lwes", conversion="party_local")
report = benchmark_operator(method, lanes=64, samples=3)
assert report.quality.exact_integer_outputs == 192
assert report.resources.public_table_bytes_by_party[0] == 0
replayed = replay_operator_benchmark(report.configuration)
assert replayed.resources == report.resources
```

## Contract and options

Component identity: `pllm/private-embedding-lookup/v1`.

| Option | Values | Meaning |
| --- | --- | --- |
| `vocabulary_size` | 1–4,096 | Public table row count |
| `precision` | `"int8"`, `"int4"`, `"mixed_4_3_3"` | One 8-bit, two 4-bit, or three 4/3/3-bit channels per coefficient |
| `repacking` | `"none"` (default), `"pack_lwes"`, `"interleave"` | Full replies, extracted-LWE consolidation, or direct strided consolidation |
| `conversion` | `"local"` (default), `"party_local"` | Local issuer receives both shares, or separate input/output-share handles with local random-OT issuance |

`lanes` is the embedding width, from 1 to 256. Each coefficient reserves one
guard bit per signed code within a 13-bit plaintext ring. Columns repeat the
selected width pattern; a final incomplete group pads with zeros. Samples are
fresh independent queries, from 1 to 16. A 128 MiB conservative allocation
estimate precedes packing and issuance; some maximum geometries reject.

Caller-owned input uses `inputs={"table": row_major_codes, "token": [row_index]}`.
Codes are already quantized, signed integers in each column's declared width.
Omitting inputs selects a public fixture. The immutable report retains neither
inputs, outputs nor their fingerprints. Configuration replay requires supplying
caller-owned data again.

## Ownership and limits

Each sample issues a fresh BFV keypair. Every returned coefficient receives an
independent uniform mask, including coefficients outside the selected outputs.
Serial one-use half-gates circuits reconstruct packed shares internally, correct
cross-slot carries, sign-extend and freshly re-share outputs. The trusted local
benchmark alone combines the final shares for an independent row oracle. Native
packing and conversion release the interpreter lock.

Reports charge padded HE request/reply frames, conversion keys, boundary labels,
public instruction estimates, provider table owners and separate setup/issuance/
online timings. Provider code and coefficient storage is asymmetric. The client
still owns its secret HE key. SEAL pool peaks, checkpoint distribution and complete
wire costs remain unknown.

Extracted-LWE packing uses native sample extraction and complete trace/interleave
to consolidate outputs. Direct interleaving implements BumbleBee's strided
variant. Both retain the selected integer profile and mask all unused output
coefficients. Automorphisms use SEAL-validated 54+54-bit key parameters; each
response must retain a positive noise budget. Setup/Galois keys, extraction
buffers and both conversion directions remain charged.

Party-local conversion hides each party's input from the other handle and returns
only its output shares. Its trusted random-OT dealer remains in-process. Local
half-gates conversion remains the default and its issuer sees both inputs.
Distributed OT setup, the paper's SiRNN, authenticated role transport,
malicious-query validation and independent cryptographic review remain absent.
Operator availability does not authorize a decoder Experiment.

The source-only per-channel quantizer diagnostic is separate from this integer
operator. It includes no paper fine-tuning. For a tied client embedding/head,
moving token lookup alone leaves the full head matrix client-owned; it does not
establish a client-memory reduction.

Nine fresh operator processes check 1,215 exact outputs. In the separate twelve-
prompt Qwen requantization diagnostic, mixed 4/3/3 matches 10/12 prefill selections,
34/36 same-token decode selections and 6/12 eight-token trajectories; no candidate
has exact logits or KV. Full-vocabulary 39+32 costs remain a non-executable
historical unrepacked projection: 1.643 GB of HE frames plus 293.35 MB of
local-conversion keys for that layout.
See [operator costs](https://github.com/blairhudson/pllm/blob/main/docs/evidence/research-packed-embedding-cost.json) and
[numeric/ownership evidence](https://github.com/blairhudson/pllm/blob/main/docs/evidence/research-packed-embedding-quality-qwen25.json).

The separate [repacking cohort](https://github.com/blairhudson/pllm/blob/main/docs/evidence/research-repacked-embedding-cost.json)
checks 3,456 outputs across eighteen fresh processes. At 4,096×64 mixed precision,
online HE/conversion frames fall from 1,642,896 to 180,624 bytes, while setup keys
and local compute increase. Full-vocabulary geometry remains unadmitted and tied
head ownership still releases zero weight bytes.
