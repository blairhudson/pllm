---
title: "Private lookup and full head"
description: "Move a tied token table and full output head to two boundary workers while retaining ordinary generation."
---

[`PrivateLookupAndFullHead`](/sdk/reference/python/pllm/roles/#privatelookupandfullhead)
(`pllm/private-lookup-full-head/v1`) selects the `boundary` slot of a prepared
`MaskedLinearCpu` Pipeline. It requires
[`PreparedBoundaryRoles`](/sdk/components/roles/prepared-boundary/).
Packed private lookup and exact ring32 full-head sharing use one immutable tied
weight owner in each boundary worker. The client receives no vocabulary matrix;
tokenization, attention, full KV, reconstructed complete logits and sampling stay
local. Generated Qwen2/Qwen3/Llama controls preserve logits, KV, tokens and RNG.

## Python SDK example

```python
from pllm import Deployment, ExecutionBudget, Experiment, Model
from pllm.profiles import MaskedLinearCpu
from pllm.roles import PreparedBoundaryRoles, PrivateLookupAndFullHead

boundary = PrivateLookupAndFullHead()
experiment = Experiment(
    name="private-vocabulary-example",
    pipeline=MaskedLinearCpu(
        Model.tiny(), boundary=boundary, topology=PreparedBoundaryRoles(),
    ),
    deployment=Deployment.local(root="local://private-vocabulary-example"),
    budget=ExecutionBudget(requests=1, max_input_tokens=64, max_new_tokens=2),
)
assert experiment.pipeline.components["boundary"] == boundary
assert experiment.resolve().composition_digest == experiment.pipeline.digest()
```

Run `examples/private_boundary.py` for ordinary SDK/gateway execution. Use
`examples/benchmarks/private_boundary.py` for build-locked, fresh-process
`BenchmarkTarget.response` / `benchmark_suite` comparisons; the same Experiment
also works with `pllm benchmark run`. See the
[provider-role guide](/sdk/run/provider-roles/#coupled-private-vocabulary-boundary).

The [matched SOTA screens](/research/sota/#coupled-private-boundary-sdk-screen)
measure lower cold-client traffic when workers already hold the source. They
also record slower decode and higher CPU/client-subprocess RSS. Checkpoint and
tokenizer distribution remain unmeasured, and child-only RSS cannot qualify a
whole-client memory tier. Embedding-only relocation would save no tied-head bytes.

The initial contract requires a tied W8A8 table without auxiliary token tables.
Supported compositions and exclusions follow the
[role guide](/sdk/run/provider-roles/#coupled-private-vocabulary-boundary).
Boundary workers must not collude; co-located children do not establish operator
independence or cryptographic review.

## Exact head transport choices

```python
from pllm.roles import PrivateLookupAndFullHead

boundary = PrivateLookupAndFullHead(
    head_dispatch="parallel", head_output_encoding="uniform_residues",
)
assert boundary.params["head_dispatch"] == "parallel"
```

`head_dispatch="parallel"` overlaps the current head's two authenticated worker
requests. Both calls drain before retirement on cancellation or partial failure.
Lookup requests retain their original ordering. `head_output_encoding="uniform_residues"`
packs exact output shares using one source-bound public geometry width: 25 bits
for a hidden width of 896. Input shares remain ring32; the client reconstructs
all signed head outputs before the original float32 dequantization and sampling.
No vocabulary matrix or weight scan moves to the client.

The defaults, `"serial"` and `"u32"`, preserve previous configuration identities.
Each alternative is explicitly selected and compiler-bound. Admission charges
parallel thread/frame owners and native codec temporaries in addition to the
original full-frame allowance. Smaller payloads do not establish lower client
peak memory. `scripts/benchmark_private_boundary_decode.py` compares all four
boundary combinations with the maintained prepared comparator through ordinary
fresh-client SDK benchmarks and complete-state audits.

The first matched Qwen2.5 150+8 SDK screen measures **52.42% faster decode** for
parallel/residue heads against serial/u32, with exact full-state/output parity and
zero observed swap growth. Its largest complete-client peak is **228.67 MiB**,
within observed Low, while median client RSS rises 1.20% and CPU 3.60%.
Against maintained prepared execution, traffic falls 23.70% and full requests
24.19%, but decode remains 32.78% slower. See the
[head-choice screen](/research/sota/#exact-boundary-decode-screen) for scope and replay.

## Source-certified per-row replies

`head_output_encoding="row_residues"` uses a separate exact width for every
vocabulary row. Select it with an independently approved `head_certificate` pin
containing an absolute local `path`, actual-byte SHA-256 `digest` and `size_bytes`.
The client authenticates this bounded public artifact; both boundary workers
recompute its row bounds against their immutable native weights. The client
continues to reconstruct every original integer and float32 logit without
receiving a vocabulary matrix.

```python
from pllm import ConfigurationError
from pllm.roles import PrivateLookupAndFullHead

def certified_boundary(approved_pin):
    return PrivateLookupAndFullHead(
        head_dispatch="parallel",
        head_output_encoding="row_residues",
        head_certificate=approved_pin,
    )

try:
    certified_boundary(None)
except ConfigurationError:
    missing_pin_rejected = True
else:
    missing_pin_rejected = False
assert missing_pin_rejected
```

The offline trusted publisher creates an artifact with
`PrivateLookupAndFullHead.publish_head_certificate(experiment, path)` using a
source recipe without row residues. Head-only import is admitted against live
host/container headroom before tensor loading. The returned pin still needs
independent publisher approval: a worker-supplied digest is not authentication.
Publication, local artifact reads and distribution have separate costs. This
selection currently supports local prepared-boundary children with tied W8A8
heads; admission retains full-frame allowances and adds certificate/codec owners.

Generated decoder/SDK checks preserve complete logits, active KV, selections and
RNG for both head kernels. A separate six-client Qwen2.5 150+8 initial screen
preserves 52.56 million checked values with zero observed swap growth: head payload
falls 8.31%, total TCP traffic 0.17%, and decode improves 2.41%, while full requests
are 1.18% slower. Largest complete-client peak is 221.66 MiB; mixed paired RSS
changes establish no memory improvement. A separate 150+64 six-client screen
preserves 486.56 million checked values with zero swap growth: TCP traffic falls
0.91%, decode improves 0.87%, full requests are effectively unchanged and
five-owner cold CPU rises 2.86%. Largest candidate peak is 217.83 MiB, also with
mixed paired RSS changes. Certificate distribution is separately budgeted;
independent confirmation remains open for both screens.
See the [source-certificate contract](https://github.com/blairhudson/pllm/blob/main/docs/research/private-boundary-row-codec-sdk.md)
and [matched benchmark](https://github.com/blairhudson/pllm/blob/main/docs/research/private-boundary-row-codec-benchmark.md).

## Exact head kernel choice

```python
from pllm.roles import PrivateLookupAndFullHead

boundary = PrivateLookupAndFullHead(
    head_dispatch="parallel", head_output_encoding="uniform_residues",
    head_kernel="byte_dot",
)
assert boundary.params["head_kernel"] == "byte_dot"
```

The opt-in kernel decomposes each full-ring input into four balanced signed-byte
limbs and reconstructs every original ring32 output. It reuses the boundary
worker's immutable weights, detects ARM dot-product support at runtime and uses
an exact scalar fallback where unavailable. Source and schedule commitments bind
the choice before worker admission. Geometry and live-payload limits precede
input conversion, limb allocation and execution.

The default `head_kernel="existing"` retains the original configuration identity.
`scripts/benchmark_private_boundary_byte_dot.py` compares both kernels through
ordinary fresh-client SDK responses, with exact state auditing and complete
client resource accounting. Historical synthetic byte-dot API measurements have
separate allocation contracts and do not establish SDK acceleration.
