---
title: "Client-owned linear roles"
description: "Place semantic projection groups at the trusted client while keeping remaining body work remote."
---

API: [`ClientLinearRoles`](/sdk/reference/python/pllm/roles/#objects-and-signatures).

`ClientLinearRoles` selects projection groups by semantic role across layers,
or by explicit `(layer_index, semantic_role)` pairs.
Supported selectors are `qkv_projection`, `attention_output`, `mlp_gate_up` and
`mlp_down`. The native compiler places matching groups locally; the bundle binds
their exact i8 weights, scales and declared biases before inventory reservation.
The selected roles must exist and some body work must remain remote.

This public prepared placement supports `MaskedLinearCpu` and
`VerifiedMaskedLinearCpu`, with native CPU or thresholded Apple Metal kernels.
Nonlinear operations remain client-local. Added client weights/scales have a
512 MiB bound. Native weights use shared resident snapshots or authenticated paged
files; admission prices the selected storage. Providers retain the public checkpoint.

`ClientLinearRoles(roles, prefix_layers=1)` selects the **union** of matching
projection roles and all projections in the first layer. Native scheduling,
bundle import, provider stages, GPU allocation and planner costs use the same
predicate; overlapping stages are counted once. Optional `layer_roles` joins the
same union. Omitting the optional selectors preserves previous component
identities. Some body work must remain remote.

For example, `ClientLinearRoles(layer_roles=((0, "mlp_gate_up"),
(1, "attention_output")))` owns only those two groups. Selectors are canonical,
distinct and bounded to 1,024 pairs with layer indices 0–255. Absent groups reject
in both native phases. Paged delivery, preparation commitments and local memory
admission retain this exact ownership declaration.

## Python SDK example

```python
from pllm import Deployment, ExecutionBudget, Experiment, Model
from pllm.preparation import PreparedInventory
from pllm.profiles import MaskedLinearCpu
from pllm.protocols import ClientBundleTransport
from pllm.roles import ClientLinearRoles

experiment = Experiment(
    "client-attention",
    MaskedLinearCpu(
        Model.tiny(),
        placement=ClientLinearRoles(["qkv_projection", "attention_output"], prefix_layers=1),
        inventory=PreparedInventory("request-sized"),
        delivery=ClientBundleTransport("zlib"),
    ),
    Deployment.local(root="local://client-attention"),
    ExecutionBudget(requests=1, max_input_tokens=64, max_new_tokens=8),
)
assert experiment.resolve().client_linear_roles == ("attention_output", "qkv_projection")
assert experiment.resolve().client_prefix_layers == 1
assert experiment.resolve().prepared_inventory_rows == 1
assert experiment.pipeline.placement.component == "pllm/client-owned-linear-roles/v1"
assert tuple(experiment.pipeline.placement.get_params()["roles"]) == ("attention_output", "qkv_projection")
```

178.97 to 148.30 MB and online bodies from 113.55 to 93.22 MB. Attention ownership
adds 44.04 MB of i8 weights, 0.20 MB of scales and a 44.04 MB native snapshot;
87.69% of declared **body linear MACs** remain remote. Peak RAM and total wire
bytes are unmeasured. See the [matched evidence](https://github.com/blairhudson/pllm/blob/main/docs/evidence/incremental-network-qwen25-2026-10-01.json).

with explicit `layer_roles`, preserving over 90% of body MACs remotely in both
prefill and decode. All-link TCP streams fall **496.05 → 473.68 MB (4.51%)** after
charging extra cold weight delivery. Client peak RSS rises **2.65%** and cold-first
CPU **3.82%**; complete cold requests rise **2.42%** despite lower online TTFT.
Outputs match with zero observed swap growth. This explicit traffic/resource
tradeoff uses the paged prepared stack and shared native 100/40 Mbps caps;
physical wire and checkpoint distribution remain unmeasured. See the
