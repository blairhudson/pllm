[`NetworkSpec`](/sdk/reference/python/pllm/deployment/#networkspec) supports
`backend="local"` static declarations and `backend="http"` authenticated discovery.
Local declarations serialize as `pllm.network_spec.v1`; HTTP trust roots serialize
as v2. The live role-host implementation admits CPU two-online-offset and prepared
Inference/Preparation execution. Other remote graphs and GPU hosting remain gated.

`PartyOffer` is a static declaration with `authenticated=False`.
`PartyTrust` approves a party/operator/origin and names a credential environment
variable. `PartySpec` installs one exact pipeline, source lock, allowed worker
roles, capacities, and bounded workload. `LivePartyOffer` adds the installed
descriptor/source, host epoch, role IDs, accepting status, and bounded expiry.
Importing a record with `authenticated=True` alone grants no live authority.

## Python SDK example

Inspect the checked-in loopback configuration from the repository root. No live
service or credential is needed for this example.

```python
from pllm import Deployment, ExecutionBudget, Experiment, Model
from pllm.deployment import LinkConditions, NetworkSpec
from pllm.profiles import TwoOnlineOffsetCpu

network = NetworkSpec.from_file("examples/networks/loopback.json")
intent = Deployment.network(
    network_id=network.network_id, network_spec_digest=network.digest
)
experiment = Experiment(
    "network-intent", TwoOnlineOffsetCpu(Model.tiny()), intent,
    ExecutionBudget(requests=1, max_input_tokens=32, max_new_tokens=2),
)
assert network.backend == "http"
assert tuple(party.credential_env for party in network.parties) == (
    "PLLM_NETWORK_A", "PLLM_NETWORK_B"
)
assert experiment.to_spec()["schema"] == "pllm.experiment.v3"
assert experiment.deployment.network_spec_digest == network.digest
assert Experiment.from_spec(experiment.to_spec()) == experiment
conditions = LinkConditions(latency_ms=10, bytes_per_second=12_500_000, loss_fraction=0.001)
assert LinkConditions.from_spec(conditions.to_spec()).digest == conditions.digest
```

API: [`pllm.deployment`](/sdk/reference/python/pllm/deployment/#objects-and-signatures)

`Deployment.network(...)` is explicit v3 intent bound to the network digest,
optionally to a snapshot digest. It has no local root. Existing local experiments
retain v2 serialization; the planner does not silently convert them into network
authority. Execution resolves and checks actual source locks rather than relying
on a documentation digest.

## Live discovery

`discover(network)` and `async_discover(network)` return `NetworkSnapshot` records.
For HTTP, credentials resolve from configured environment references; an optional
`credentials` mapping is keyed by those reference names and contains local values.
Public files contain reference names only. Origins require HTTPS except loopback
HTTP; redirects and embedded URL credentials are rejected.

Discovery checks approved membership, fetches each installed party offer, and
preserves local client authority. An optional directory advertises membership,
not new trust roots. Discovery neither measures links nor reserves capacity.
Directed `LinkObservation` estimates carry source, age, expiry, and uncertainty;
missing required links cannot be treated as free transport.

Operator separation checks compare **declared** identities. Two loopback hosts
with different declarations still do not prove physical operator independence.
The example's long-lived local client seed is not a substitute for fresh remote
offers; planning policies and live admission check current observations.

The [two-party fixture](https://github.com/blairhudson/pllm/blob/main/examples/networks/README.md)
generates locked checkpoint and `PartySpec` files. Its
[`two_party.py`](https://github.com/blairhudson/pllm/blob/main/examples/networks/two_party.py)
run path discovers fresh offers before constructing a request.

## Controlled local links

[`LinkConditions`](/sdk/reference/python/pllm/deployment/#linkconditions) describes
bounded provider-egress controls, not a measured offer: delay, bytes/second, seeded
random loss. `build_roles(..., docker=True, docker_network=conditions)` applies
Linux netem in each provider namespace through a separate measurement helper.
The provider image remains minimal; only the helper holds network-administration
capability and tools. Both images/containers are owned by the ordinary supervisor.

Run `pllm benchmark run --docker --tiny --docker-network-profile examples/benchmarks/docker_link.json`
from the repository root. Shaping is **provider-egress only**, also affecting
provider telemetry; it is not a symmetric WAN model. Backend and profile digests
must match before benchmark rankings are admitted.

Reports separate helper CPU/memory from provider resource samples and conserve
six directed prepared service links using IPv4/TCP kernel-hook counters. Each
peer transfer is counted at one endpoint. These counters include service control,
ACKs and retransmissions; exclude telemetry, DNS, IPv6, cold checkpoint downloads
and the host application API. Kernel offload and post-hook drops also prevent
calling them complete physical wire bytes. Interface totals remain a separate scope.
