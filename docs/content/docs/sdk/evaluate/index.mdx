---
title: "Evaluate PLLM"
description: "Measure comparable execution cohorts and keep performance, quality, cost, and assurance separate."
---

Run [matched benchmarks](/sdk/evaluate/benchmark/) using
[`pllm benchmark run`](/cli/reference/benchmark/run/), then choose
[metric definitions](/sdk/evaluate/metrics/) that reflect the desired phase
and direction. [Search](/sdk/evaluate/search/) generates valid immutable
candidates; it does not execute them. [Evidence](/research/evidence/) binds
results to plan, model, environment, and workload. Quality and assurance are
separate outcomes, not implied by a faster median. The
[experimentation system](/research/recipes/experiments/) connects these steps
to reproducible research.

## Python SDK example

```python
from pllm.metrics import Latency, Throughput

latency = Latency(statistic="median", phase="full")
throughput = Throughput(basis="tokens")
assert latency.component == "pllm/latency"
assert throughput.component == "pllm/throughput"
```

These objects declare what to measure; they do not fabricate observations or
launch inference. For a real run use a supported
[Experiment](/sdk/experiments/) with `pllm benchmark run --experiment
experiment.py:experiment --trust-python` and report only matched cohorts.

API: [Metric objects](/sdk/reference/python/pllm/metrics/#objects-and-signatures)
