description: "Measure one operation or a complete request with shared isolation, evidence and retest contracts."

`BenchmarkTarget` selects the work. `Sampling` selects independent processes and
repetitions. `benchmark_suite` owns admission, deadlines, cleanup and checkpointed
evidence. Small targets execute their selected primitives without starting a decoder.

## Python SDK example

Measure a selected stage in three fresh processes:

```python
from tempfile import TemporaryDirectory
from pllm import Deployment, ExecutionBudget, Experiment, Model
from pllm.metrics import BenchmarkTarget, Sampling, benchmark_target
from pllm.profiles import MaskedLinearCpu

experiment = Experiment(
    "stage-example", MaskedLinearCpu(Model.tiny()),
    Deployment.local(root="local://stage-example"),
    ExecutionBudget(requests=1, max_input_tokens=16, max_new_tokens=2),
)
with TemporaryDirectory() as directory:
    result = benchmark_target(
        BenchmarkTarget.preparation(experiment, role="mlp_gate_up", layer=0, rows=16),
        sampling=Sampling(processes=3),
        output=f"{directory}/stage-results.json",
    )
    assert result.to_dict()["complete"]
    assert all(row.to_dict()["status"] == "completed" for row in result.results)
```

The native semantic schedule selects the stage and checks its shape. The default
fixture uses public synthetic integer weights; `weights="checkpoint"` resolves
the source lock and quantizes only the selected artifacts through the ordinary
stage loader. Configuration-only geometry and checkpoint values have different
evidence identities. The integer oracle runs after the timed sample and captured
process high-water mark. Each issuance gets fresh OS randomness.

## Available targets

| Constructor | Executed scope |
| --- | --- |
| `runtime(role)` | Fresh Python/SDK/NumPy/HTTPX/native/client/prepared-client/Preparation import process, including import CPU, peak RSS and imported module roots. |
| `geometry(experiment)` | Native lowering and schedule, without tensor values. |
| `artifacts(experiment)` | Selected immutable weight-file import or bind through the real shared/copied snapshot paths. |
| `preparation(experiment)` | Local fresh mask expansion, exact selected-stage products and correction-file output. |
| `preparation_batch(experiment)` | Bounded local cross-inventory correction batches through the installed SDK owner. |
| `stage(experiment)` | Local masked integer arithmetic and existing residue codecs, with an independent signed-integer oracle. |
| `operator(component)` | Existing `benchmark_operator` implementation, oracles, citations and one-use material. |
| `state(experiment)` | Bounded synthetic full-KV roundtrip, ordinary local attention, or sealed-file import in a fresh child process. |
| `recurrence(experiment)` | Source-shaped exact gated-delta transitions, retained state and reusable scratch. |
| `checkpoint(experiment)` | Compiled full-KV publication and fresh-process exact continuation with layer pages or context-graph storage. |
| `projection(experiment)` | Native state geometry or explicitly assumed restart costs; results remain estimates. |
| `response(experiment)` | Ordinary role supervisor and benchmark driver, including cold/repeat/ordered-sequence requests. |

Preparation `chunk_rows` bounds mask rows in a local calculation. It does not
implement output-stripe push/ack assembly. The experimental `kernel="digit4"`
and `"digit8"` choices run exact digit-lifted CPU float32 GEMM with conversion and
reconstruction charged. They are benchmark targets, not serving kernel components.
The separate `kernel="digit8_native"` target exercises Rust-owned, bounded CPU
SGEMM tiles with resident or paged weights. Its exact 16/24/32-bit reconstruction
is also selectable on Apple Silicon through
`ModelAwareCorrections(kernel="digit8", min_rows=64)`. Preparation uses ordinary
integer kernels below the declared row threshold. Serving memory admission prices
each concurrent workspace. These selections have independent evidence from the
earlier NumPy-based screen.

Runtime roles are `"python"`, `"sdk"`, `"numpy"`, `"transport"`, `"native"`,
`"client"`, `"prepared_client"` and `"preparation"`. Each imports into its own
fresh child. Their footprints overlap and must not be added or subtracted as
isolated dependency costs. `execution.details.imported_module_roots` explains
which dependencies that entry point actually loaded.

Stage transport and verified-stage targets return explicit unsupported results.
Synthetic sealed state is not a continuation credential: private KV, logits,
pending-token provenance and reusable protocol material cannot be imported through
this target. Its trusted revision/key owner remains separate from a fresh reader.

## One runner for whole responses

```python
from tempfile import TemporaryDirectory
from pllm import Deployment, ExecutionBudget, Experiment, Model
from pllm.metrics import BenchmarkTarget, Sampling, Scenario, benchmark_target
from pllm.profiles import MaskedLinearCpu

prepared = Experiment(
    "response-example", MaskedLinearCpu(Model.tiny()),
    Deployment.local(root="local://response-example"),
    ExecutionBudget(requests=2, max_input_tokens=64, max_new_tokens=2),
)
with TemporaryDirectory() as directory:
    result = benchmark_target(
        BenchmarkTarget.response(
            prepared, scenario=Scenario.repeat(count=2, max_output_tokens=2),
        ),
        sampling=Sampling(processes=1, timeout_seconds=90, memory_bytes=2 << 30),
        inputs={"prompt": "a"},
        output=f"{directory}/response-results.json",
    )
    assert result.to_dict()["complete"]
    assert result.results[0].to_dict()["status"] == "completed"
```

Response sampling uses one scenario per process. A repeat contains its cold first
request and later requests on the same client. `Scenario.sequence(count=...)`
accepts `inputs={"prompts": [...]}` for ordered request contexts. Each context may
be plain text or a bounded list of text-only `{"role": ..., "content": ...}` messages,
using the ordinary benchmark driver's validation. Checkpoints stay
cached; runner-owned client caches start fresh. Whole-topology admission precedes
provider launch. `wan=WanConditions(...)` uses the existing enforced backend.

Seven serving metrics have separate contracts: client peak RSS and cold CPU,
Preparation cold CPU and sampled request-window RSS, online TTFT, N−1 decode
throughput, and all-link TCP-stream bytes. Covered application bodies are another
metric. Missing roles, unmetered streams and zero decode denominators remain null.
Import-process memory, parent-only memory and full-client memory never share an
implicit measurement scope.

### Research client-stage ownership

An explicit response-only selection can compare Python ownership with a bounded
native owner for one compiled remote stage:

```python
from pllm import Deployment, ExecutionBudget, Experiment, Model
from pllm.metrics import BenchmarkTarget, Scenario
from pllm.profiles import MaskedLinearCpu
from pllm.protocols import MaskedLinear

prepared = Experiment(
    "native-stage-example", MaskedLinearCpu(Model.tiny()),
    Deployment.local(root="local://native-stage-example"),
    ExecutionBudget(requests=2, max_input_tokens=64, max_new_tokens=8),
)
research_prepared = prepared.with_params(
    pipeline__linear=MaskedLinear(
        request_encoding="stage_packed", output_encoding="row_residues",
        prefill_chunk_rows=4,
    ),
)
target = BenchmarkTarget.response(
    research_prepared,
    scenario=Scenario.repeat(max_output_tokens=8),
    client_stage={"owner": "native", "role": "mlp_gate_up", "layer": 0},
)
assert target.to_spec()["parameters"]["client_stage"]["owner"] == "native"
```

The Experiment must select unverified prepared execution on the native backend,
lazy inventory, packed requests and row-residue outputs. Unsupported compositions reject. Use
`owner="python"` for the matched control in the same suite. Both selections run
the complete SDK response through separate provider children; Python imports,
tokenization, transport and decoder state remain charged to the client.

`execution.details.client_stage_research` records the checked binding, selected
semantic stage, executed rows and stage-local CPU/wall time. The seven serving
metrics still measure their ordinary whole-response windows. This fixed research
adapter is not a Pipeline component or a native decoder. Exact generated
Qwen2/Qwen3/Llama logits and KV are covered separately from checkpoint serving
measurements. The reusable workload study is
`benchmarks/research/client_stage_ownership.py`. Its independent Qwen2.5
short-workload confirmation increases client peak RSS by 1.32%; exact arithmetic
compatibility has not established a memory benefit or justified wider native
ownership. Full evidence and replay: `docs/research/client-stage-ownership.md`.

### Research MLP working sets

`BenchmarkTarget.response(experiment, client_mlp={"tile_rows": 16})` additionally
executes compiler-admitted initial-prefill MLP regions in row tiles. Use
`{"tile_rows": 0}` as the matched full-tensor control. The native pass binds the
original gate/up, SiLU, multiply and down operations, their exclusive consumers,
public tile bound and source schedule. Both arms retain the same eligibility and
metadata instrumentation. Decode and continuation use the original schedule.

This fixed research selector requires unverified prepared execution and rejects
protected nonlinear or retained-state contracts. Tiling retires wide intermediates
before the next tile, while keeping body weights remote and every mask row one-use.
`execution.details.client_mlp_research` reports actual tile counts and separately
counted public Python metadata bytes. Whole-response RSS, CPU, traffic and latency
remain ordinary measured metrics. Existing conservative admission still applies.

`benchmarks/research/client_stage_ownership.py --working-set` screens 16- and
64-row tiles through the same `FrontierStudy` workloads and confirmation runner.
Exact generated Qwen2/Qwen3/Llama logits and KV are covered separately from
checkpoint response measurements. Contracts and replay:
`docs/research/mlp-working-set-reference.md`.

### Client construction attribution

`BenchmarkTarget.response(experiment, client_metadata=True)` traces Python
allocations while the ordinary client compiles, validates, sizes preparation and
binds its semantic runtime. `execution.details.client_metadata.phases` records
each phase's new retained/peak traced bytes, CPU, wall time and unique public
metadata object bytes. Nested compilation stays inside its outer runtime phase.
Tensor storage and native allocations are outside the public-metadata count;
construction traces still include the temporaries that those functions allocate.

Tracing has a separate measurement identity and cannot rank against untraced
serving results. The fixed executor restores its hooks and tracing ownership on
failure. Use `benchmarks/research/client_stage_ownership.py --metadata` to retain
exact-build coverage through `FrontierStudy`. This measures the first load-ready
artifact gate; no subtraction of traced bytes from RSS predicts an artifact win.

### Streaming sealed-state reference

`BenchmarkTarget.state(..., storage="sealed_stream")` keeps the existing
synthetic state fixture's AES-GCM frames and trusted-head contract, while
encrypting through bounded 1 MiB buffers and decrypting into one admitted record
allocation. Authentication completes before any plaintext record is returned.
`roundtrip`, `attention` and `restart` use the same frozen geometry and arithmetic
as `sealed_local`; publication, restore-child CPU/RSS and private disk stay visible.
`benchmarks/research/state_working_set.py` compares resident, one-shot and streaming
layouts at multiple context lengths. This is a storage/attention gate, not yet
a compiler-bound layer-swapped decoder or durable conversation credential.

### Correction output stripes

`BenchmarkTarget.preparation(..., output_columns=256)` measures a compiler-selected
stage through separate, fresh local pipe peers. `output_columns=0` uses one full
output stripe as its matched control. Each stripe needs an authenticated, ordered
acknowledgement; only the final complete seal reaches READY. Malformed frames,
replay, acknowledgement substitution and cancellation retire incomplete owners.

The target keeps full input batches for native integer or `digit8_native` kernels.
Full input/output masks remain charged. Reports include both process CPU owners,
separate endpoint peaks, stripe/ack/control bytes, initial weight binding and
private correction files. `benchmarks/research/correction_stripes.py` compares
full, 256- and 1,024-column layouts. This local fixture has no HTTP role inventory,
paged-weight stripe kernel, WAN result or complete-response performance claim.

### Checkpoint-backed decoder restart reference

`BenchmarkTarget.state(..., operation="decoder_restart", storage="sealed_local")`
adds an actual bounded decoder consumer to the synthetic restart mechanics. It
requires the explicit W8A8 `prefix_f32` baseline composition, at most 128 public
fixture tokens, 16 MiB source weights at float32 and an 8 MiB sealed-frame bound.
A trusted fixture issuer authenticates full KV, logits, executed history and the
pending greedy token against the compiled binding and continuation contract.

A fresh interpreter reloads/revalidates the source, authenticates the checkpoint,
checks full-state geometry and pending-token provenance, then runs two exact
continuation steps. Each linear call issues fresh local prepared material. Old
snapshot seals, credentials, inventories and masks never enter persistent state.
Reports charge original bootstrap/publication and new-client import/restore,
separate peaks and fresh arithmetic bodies. Keys and trusted heads stay with the
issuer; this is not persistent key management, an SDK conversation importer or
independent provider transport. Replay with `benchmarks/research/decoder_restart.py`.

## Propagate required measurements

### Installed frontier targets

- `BenchmarkTarget.recurrence(experiment, owner="owned")` derives gated-delta
  geometry from the admitted source plan, executes synthetic projected inputs,
  and checks every output/final-state bit. `owner="copy_reference"` is the matched
  control. State, scratch and process RSS retain separate owners.
- `BenchmarkTarget.checkpoint(experiment, storage="context_graph")` compares the
  installed `CheckpointSession` with `storage="layer_pages"`. It requires a
  bounded local W8A8 `prefix_f32` checkpoint and `Sampling(memory_bytes=1 << 30)`.
  Fresh-process restoration checks all logits/KV and pending-token provenance.
  Publication, restore import, continuation and KV audit are timed; initial
  source loading and issuer/child peaks remain separate.
- `BenchmarkTarget.preparation_batch(experiment, inventories=4, batch_size=4)`
  measures independent one-use inventories sharing a native stage snapshot.
  `batch_size=1` is the serial control. `window_rows` bounds row buffers; kernels
  include `native`, `digit8_native`, `metal` and `adaptive`. It measures local
  issuance/attribution/storage, with no arrival queue or provider transport.

Use the [installed frontier example](https://github.com/blairhudson/pllm/blob/main/examples/benchmarks/frontier_sdk.py)
for complete immutable suites. These target-local metrics remain separate from
the seven whole-response serving metrics and historical research timings.

### Study propagation

```python
from tempfile import TemporaryDirectory
from pllm import Deployment, ExecutionBudget, Experiment, Model
from pllm.evidence import EvidenceRegistry
from pllm.metrics import (
    BenchmarkCase, BenchmarkSuite, BenchmarkTarget, BuildRef, Sampling, benchmark_suite,
)
from pllm.profiles import MaskedLinearCpu
from pllm.search import FrontierStudy, Variant

experiment = Experiment(
    "study-example", MaskedLinearCpu(Model.tiny()),
    Deployment.local(root="local://study-example"), ExecutionBudget(1, 16, 2),
)
suite = BenchmarkSuite(
    (BenchmarkCase("prepare", BenchmarkTarget.preparation(experiment),
                   BuildRef.capture()),),
    Sampling(processes=3),
)
study = FrontierStudy(
    suite,
    variants=(Variant("digit4", {"kernel": "digit4"}),
              Variant("chunks", {"chunk_rows": 4})),
    interactions=(("digit4", "chunks"),),
)
work = study.plan(max_trials=12)
assert work.suite is not None
with TemporaryDirectory() as directory:
    run = benchmark_suite(work.suite, output=f"{directory}/study-results.json")
registry = EvidenceRegistry().register_all(run.results)
coverage = study.plan(registry).coverage
frontier = study.snapshot(run, metrics={"target.cpu": "min"})
assert coverage.to_dict()["selected_trials"] == 0
assert frontier.to_dict()["groups"][0]["status"] == "exploratory"
```

Variants use immutable `with_params` patches. `pipeline__...` patches modify the
target's Experiment. Explicit interactions and leave-one-change-out cases remain
visible. Trial budgets count process executions. Selected neighbors always rerun
their control in the same cohort; partial old cohorts cannot supply the control.
Serialized targets accept existing component-slot aliases such as
`pipeline__preparation__kernel`; setting an entire optional slot to `None` removes
it. Duplicate aliases and overlapping paths reject.

`BuildRef.capture()` inspects installed Python/native files, dependency records,
numeric backend metadata, OS and public CPU/memory identity in a separate process.
A different build creates retest gaps. Changed-path dependency hints prioritize cases; they never
transfer measurements to another build. Unpinned builds cannot satisfy current-build
coverage. Response/operator inputs and external source files require fresh
revalidation; identical public case specs cannot certify unchanged private prompts,
caller-owned values or checkpoint contents. Their historical results stay visible,
but the planner schedules them again. Self-contained synthetic fixtures can close
coverage for an exact build and sampling policy.

`study.snapshot(run)` ranks only comparable, complete cells. Unknown metrics and
failed/blocked/unsupported cases stay explicit. A separately measured confirmation
run can be attached with `confirmation=...`; it needs another cohort and at least
three independent processes. Exploratory medians are not statistical confidence
intervals or an automatic recommendation to change an application.

`study.confirm(screen, cases=[...])` constructs a fresh three-process finalist
cohort with each finalist's control. Omitting `cases` nominates measured Pareto
neighbors. The same `FrontierWork.inputs(...)` mapping supplies private inputs;
`study.snapshot(screen, confirmation=confirmed)` binds both measured cohorts.
Nominations require complete comparable screen measurements.

The maintained serving study in
`benchmarks/research/prepared_frontier_study.py` starts from
`examples/prepared_sdk.py` and declares delivery, residency, reuse, prefill and
Preparation-kernel ablations. `scripts/benchmark_prepared_frontier.py` exports the
exact study, coverage plan, canonical run and seven-metric frontier together.
Its generated-checkpoint control runs with:

```bash
python -m scripts.benchmark_prepared_frontier --tiny \
  --output target/prepared-study.json
```

`--plan-only`, `--history`, `--changed-path` and `--max-trials` expose coverage
planning; `--confirm SCREEN --nominate CASE` schedules independent confirmation.
Checkpoint-backed runs require the explicit local artifacts documented with the
study. A new build or changed recipe creates new measurements rather than
inheriting old performance.

## Evidence and privacy

`BenchmarkResult` v2 extends the existing registry with source/numeric/state,
build, fixture, oracle, lifecycle, metric-window and owner commitments. V1 records
keep their existing interpretation. Private inputs and the per-suite cohort salt
travel over stdin, never argv, reports or failure strings. Immutable JSON specs
contain public configuration only.

Each completed case checkpoints atomically. Existing output paths reject. A
timeout or cancellation retires the owned process tree and temporary files.
Interrupted files remain incomplete evidence; reruns create a new cohort and fresh
one-use material. They do not resume a private session.

Run the complete public example with:

```bash
python examples/benchmark_targets.py --output target/stage-study.json
```
