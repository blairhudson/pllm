---
title: "Lower a model"
description: "Turn bounded decoder configuration into a semantic prefill/decode graph without loading weights."
---

[`lower_model`](/sdk/reference/python/pllm/#objects-and-signatures) accepts
configuration bytes or a mapping plus explicit batch, input-token, and
new-token limits. Model-family adapters emit the same operator and state
vocabulary; unsupported configuration variants fail before compilation. The
returned immutable `ModelPlan` does not resolve checkpoint files or choose an
inference profile. [Sources](/sdk/models/sources/) and
[family contracts](/sdk/models/families/) are separate decisions.

## Python SDK example

```python
from pllm import lower_model

config = {
    "model_type": "qwen2", "hidden_size": 64, "intermediate_size": 192,
    "num_hidden_layers": 2, "num_attention_heads": 4,
    "num_key_value_heads": 2, "vocab_size": 256,
    "max_position_embeddings": 128, "hidden_act": "silu",
    "rms_norm_eps": 1e-6, "rope_theta": 10000.0,
    "tie_word_embeddings": True,
}
plan = lower_model(config, batch=1, max_input_tokens=16, max_new_tokens=4)
assert plan.to_dict()["adapter"] == "pllm.qwen2.v1"
assert plan.prefill["query_sequence"] == 16
```

For real inference, use a compatible [Model](/sdk/models/) inside a supported
[Experiment](/sdk/experiments/) and run
`pllm gateway --local --experiment experiment.py:experiment --trust-python`
after installing optional `he` via [Installation](/learn/installation/).
Lowering alone never runs that workflow.

API: [`lower_model`](/sdk/reference/python/pllm/#objects-and-signatures)
