PLLM's current public-weight path has three roles: a customer-controlled client,
a trusted preparation service, and an inference provider. Prompt text, token IDs,
activation scales, attention state, sampling, and decoded output stay in the
client. Preparation and inference each hold the public transformer body but never
receive enough information alone to recover an activation under the stated
non-collusion assumption.

## Current path in one minute

1. **Prepare offline.** The client registers a committed inventory, authorizes it
   through preparation, and sends one root seed and row count per remote stage.
   Preparation expands masks and pushes `W*r-s` batches one way to inference.
2. **Seal before use.** Inference acknowledges every batch and reports `READY`
   only after all committed stages are loaded.
3. **Reserve for a response.** The client reserves enough rows for prompt prefill
   and decode. A reservation is consumed or burned; it never returns to inventory.
4. **Run online with inference only.** Each row sends a ticket and `x-r` and
   receives `W*x-s`. The client adds `s` and center-decodes.
5. **Reuse or refill while idle.** Unreserved in-memory rows may serve later
   chats. Refill never overlaps an online response.

Prompt prefill uses one compact ticket vector and packed matrix per stage. Decode
uses one ticket per stage over a persistent client-to-inference connection. Stages
select the smallest exact `u16`, `u24`, or `u32` ring from their signed output
bounds. Public token lookup and output-head matrices execute locally; only the
transformer body is remote.

Inference conventionally listens on `8000`, preparation on `8001`, and the local
gateway on `8080`. Ports are not security controls. Plaintext belongs only at the
client or local gateway inside the customer boundary.

## Claim boundary

The public protocol assumes both services are honest-but-curious and do not
collude. Preparation must erase expanded masks. Authentication and commitments
reject malformed or mismatched traffic but do not prove correct model execution,
operator independence, or erasure. Timing, stage names, tensor shapes, scheduling,
and approximate lengths remain visible.

Inventory is memory-only. Restart or configured idle expiry discards it.
Cancellation, failure, timeout, and early completion burn every unused row in the
affected reservation. This source is alpha research software, not a production
security certification.

Public seeded preparation performs no BFV work. TenSEAL-backed blinded,
confidential-weight, and direct-FHE paths remain optional legacy/research modes
with different assumptions and performance. Historical paper results do not
measure the current public path.
