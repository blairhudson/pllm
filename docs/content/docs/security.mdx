## Public path actors

| Role | Private or trusted state | Data received from another role |
| --- | --- | --- |
| Client or local gateway | Prompt, tokens, activation scales, attention state, root seeds, masks, sampling, decoded output | Public bundle, acknowledgements, `W*x-s` |
| Trusted preparation | Public transformer body; expanded masks until erased | Inventory authorization, stage root seeds and row counts |
| Inference | Public transformer body and prepared corrections | Inventory authorization, tickets, and `x-r` |

The public bundle gives the client quantized token lookup and output-head matrices.
Those vocabulary boundaries execute locally. Preparation and inference retain the
remote transformer body.

## Offline before READY

An inventory binds model, body, stage, weight, shape, quantization, ring, wire
width, and attempt budget. The client sends preparation one authorization and one
domain-separated root seed per remote stage. Preparation derives one-time `r`,
`s`, and tickets, computes batched `W*r-s`, and pushes corrections one way to
inference's fixed `/v1/he/corrections/ws` endpoint.

Only the provider-push credential can authenticate that WebSocket. Its URL is
derived from preparation's configured inference origin; clients cannot select a
callback destination. Preparation waits for bounded acceptance acknowledgements and
must erase expanded masks. Inference reports `READY` only after every stage batch
is present and the client seals the inventory.

## Online after reservation

Each response reserves a row range. Inference receives a one-time ticket and
`x-r`, consumes the matching correction atomically, and returns `W*x-s`. The
client adds local `s` and center-decodes in an exact `u16`, `u24`, or `u32` ring.

Prefill sends compact ticket vectors and packed matrices. Decode sends one ticket
per stage over a persistent client-to-inference connection. Preparation is idle
and receives no online request. Refill can run only after all online responses for
that client are finished.

Rows never return to availability after reservation. Cancellation, timeout,
failure, rejected work, and early completion burn unused reserved rows as well as
attempted rows. Process restart or prepared-session idle expiry discards all
memory-only inventory.

## Assumptions and leakage

The claim is honest-but-curious and non-colluding. Preparation must follow the
protocol, erase masks, and not collude with inference. Inference must execute the
documented computation. Authentication and commitments do not prove either fact.
Self-hosting preparation keeps its trust inside the client boundary; placing it
under the inference operator does not satisfy non-collusion.

## Training-data boundary

The public path does not send plaintext prompts, token IDs, decoded output, or
unmasked activations to either remote role. Under protocol compliance, SHAKE-256
pseudorandomness, mask non-retention, and non-collusion, the data plane removes the
direct plaintext feed either provider could otherwise retain for training. This is
a technical barrier rather than only a contractual promise, but not a universal
no-learning guarantee: metadata remains visible, collusion defeats the split,
Python memory release is not verified physical zeroization, and a compromised
client can still expose content.

Both services observe model IDs, stage names, shapes, timing, scheduling, failure
patterns, and approximate lengths. Anyone who obtains both seed-side information
and masked online activations can recover private values. Use distinct TLS origins
away from loopback and separate credentials for every channel.

## Not provided

- No protection against arbitrary malicious or colluding services.
- No proof of operator independence, secure erasure, or correct model execution.
- No model-confidentiality guarantee from guarded query limits: a modified client
  still sees intermediate outputs and can make chosen-input queries.
- No security conclusion from zero literal prompt bytes in telemetry.
- No production certification, side-channel audit, or universal deployment
  hardening claim.

The authenticated arithmetic command is a simulator. Blinded confidential-weight
and direct-BFV modes are optional legacy/research paths, not the current public
protocol and not stronger defaults.

## Operational rules

Keep client and local gateway inside the client boundary. Disable external
prompt tracing and payload logs. Protect config and model paths. Use loopback HTTP
only for local evaluation; remote inference and preparation require distinct HTTPS
origins.

The provider's prepared-session idle setting controls inventory lifetime. Client
HTTP timeout, preparation correction-ACK timeout, rendezvous timeout, and proxy
WebSocket idle timeout are separate controls. A correction connection may
reconnect for a later inventory; a dropped decode connection terminates the
current execution and burns its unused reservation.

The source distribution's root `SECURITY.md` contains vulnerability-reporting
guidance. This static site intentionally does not embed an assumed repository URL.
