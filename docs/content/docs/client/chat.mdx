---
title: "Chat from the terminal"
description: "Prepare while idle, then stream over the client-to-inference path."
---

After [configuration](/docs/client/configuration):

```bash
pllm chat
```

Override nonsecret connection fields for one invocation when needed:

```bash
pllm chat \
  --server http://127.0.0.1:8000 \
  --preparation-url http://127.0.0.1:8001 \
  --model demo-model
```

## Lifecycle

Before displaying the first prompt, chat creates and seals a public prepared
inventory. Before each later response it tokenizes locally, calculates the exact
row requirement, and refills only if the client is idle and too few rows remain.

Once a response starts, preparation receives no requests. Prompt prefill uses
compact multi-row stage messages to inference. Decode reuses the persistent
client-to-inference connection. Cancellation, transport failure, or early output
burns all unused rows reserved for that response.

## Commands

| Command | Behavior |
| --- | --- |
| `/clear` | Start new local conversation state |
| `/models` | List models exposed by inference |
| `/audit` | Show local privacy and traffic counters |
| `/config` | Show active nonsecret connection settings |
| `/help` | Show commands |
| `/quit` | Close client and discard its memory-only inventory |

Use `--no-stream` to print only after a response completes. Use
`--max-output-tokens` to change the reservation plan as well as generation limit.

`/audit` separates preparation seed/correction traffic, masked online traffic,
stage calls, inventory rows, bundle network/cache use, and forbidden preparation
attempts during online execution. Counters describe this process; zero literal
prompt bytes is not proof that timing and shape metadata are harmless.

## Local plaintext

Terminal history, screen capture, process tracing, and application logs can record
plaintext even when services do not receive it. Run chat inside the customer
boundary and protect `~/.config/pllm/chat-history` as sensitive conversation data.
