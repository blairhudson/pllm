title: "Deploy with systemd"
description: "Run inference and preparation as separate protected services."

## Install

Install this repository at `/opt/pllm`. Create a dedicated `pllm` system user,
resolve dependencies, and run `PLLM_NATIVE_CACHE=/var/cache/pllm/native uv run pllm build` before making the service
filesystem read only. The unit expects `/opt/pllm/.venv/bin/pllm`.

Copy `deploy/pllm-provider.service` and `deploy/pllm-preparation.service` to
`/etc/systemd/system/`. Configure `/etc/pllm/provider.env` and
`/etc/pllm/preparation.env` from their examples. Configure distinct client,
preparation, and correction-push credentials; the correction-push value is shared
only between provider and preparation. Set preparation's fixed inference URL. Keep
preparation inside the customer boundary or at an independently trusted
operator. Keep checkpoints outside home directories because the units protect
those directories.

```bash
sudo chmod 600 /etc/pllm/provider.env
sudo chmod 600 /etc/pllm/preparation.env
sudo systemctl daemon-reload
sudo systemctl enable --now pllm-provider
sudo systemctl enable --now pllm-preparation
sudo systemctl status pllm-provider
sudo systemctl status pllm-preparation
```

Both services bind to loopback. Place configured TLS reverse proxies in front
of remote endpoints, set request size and timeout limits, and disable payload
logging. Pass WebSocket upgrades and `Authorization` for
`/v1/he/corrections/ws`; set its frame limit to the prepared-payload limit plus
the bounded channel header and keep idle timeout above expected decode pauses.
The local plaintext gateway remains inside the customer's trust
boundary.

The public path stores no reusable preparation inventory. A client creates and
burns a fresh seed for every stage attempt.
