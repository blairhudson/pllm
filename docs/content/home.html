Privacy can turn idle compute into a global utility.

When operators do not need access to client language, trust stops being the admission ticket to useful compute. Capacity can compete on price, latency, location, energy source, and availability instead.

01

Open the supply side

Independent providers could sell compatible projection capacity without receiving plaintext prompts. Participation can depend on protocol and service quality rather than a hyperscale trust brand.

02

Follow the sun

Masked public-model work could be routed toward regions with abundant renewable generation or otherwise stranded capacity. PLLM does not yet implement that scheduler or prove an energy saving.

03

Compete down token cost

A broader supplier base can reduce concentration and create price pressure. Actual savings must include preparation, bandwidth, burn rates, client compute, and market operations.

04

Remove the direct training feed

On the documented path, providers receive zero literal plaintext prompt or token bytes. Under the stated masking and non-collusion assumptions, the data plane removes the direct plaintext feed they could otherwise retain for training.

⌁ CLIENT

Consume private inference without large-scale rewrites.

The text interface follows the Responses API, with direct PLLM, OpenAI SDK, and OpenAI Agents SDK integrations. Inventory preparation happens automatically before online execution.

with OpenAI() as client:
    response = client.responses.create(
        input="Explain prepared inference.",
        max_output_tokens=64,
    )
    print(response.output_text)

▦ SERVICES

Run preparation offline and inference online.

Both services load the same public transformer body. Trusted Preparation builds one-time corrections before requests; untrusted Inference stores and consumes them without receiving plaintext.

# Online service: stores corrections,
# then serves masked stage requests.
pllm serve "$PLLM_MODEL_SOURCE" \
  --weights public \
  --api-key "$PLLM_API_KEY" \
  --provider-push-api-key \
    "$PLLM_PROVIDER_PUSH_API_KEY"
# Offline service: computes W·r−s and
# pushes sealed inventory before chat.
pllm preparation serve \
  "$PLLM_MODEL_SOURCE" \
  --api-key "$PLLM_PREPARATION_API_KEY" \
  --inference-url http://127.0.0.1:8000 \
  --push-api-key \
    "$PLLM_PROVIDER_PUSH_API_KEY"

Offline work stays offline.

The SDK fills insufficient inventory before opening an online session. Preparation never enters an active response path.

Commit, prepare, acknowledge.

The client authorizes an inventory and sends one root seed per remote stage. Preparation expands one-time masks, pushes W·r−s batches to inference, and waits for durable acceptance. Inference reports READY only after every stage is loaded.

Client → seed batch → Preparation → W·r−s → Inference
Correction never returns to the client.

Reserve once. Pack prompt rows.

Token lookup runs locally. Each remote stage receives one compact ticket vector and one packed x−r matrix for all prompt rows. The client applies the local output head only to the final prefill row.

ticket[] + (x−r)[] → W·x−s
u16, u24, or u32 is selected per stage.

Keep one online connection.

Decode reuses a persistent client-to-inference WebSocket. Preparation remains idle. Every stage consumes one ticket; completion, cancellation, or failure burns every unused reserved row. Refill can start only after the response closes and the client is idle.

Client + s → center-decode → local state + sampling
No ticket or mask is reused.
