# Existing-model execution frontier

Five executable research slices, authorized together. The target remains an
existing open-model checkpoint; auxiliary drafters may help execute that target.
Source, numeric, privacy and one-use material contracts remain explicit.

1. **Load-ready client:** source/build-bound execution metadata and native owners.
   Measure complete construction and client execution, including runtime imports;
   metadata-only savings cannot establish a thin-client result.
2. **Transactional tiered state:** execute the original full-KV attention with
   bounded layer residency, authenticated commits and exact rollback/restart.
   Charge disk, authentication, publication and state/temporary overlap.
3. **Checkpoint drafting:** use an existing smaller checkpoint with a checked
   token boundary, exact target verification and charged rejected work. Establish
   held-out acceptance and complete costs before provider speculation.
4. **Streaming Preparation:** bounded credit-based correction delivery, then
   jointly price kernel batching, masks and transport. READY requires all ordered
   acknowledgements; errors retire every outstanding one-use attempt.
5. **Stage/phase compilation:** synthesize heterogeneous schedules from compatible
   installed implementations and complete measured costs, under joint resource
   bounds. Preserve the source decoder and validate runtime dispatch independently.

Each slice gets a separate implementation/evidence commit. Generated fixtures
test ownership and exact arithmetic; pinned checkpoints test the actual target.
First gates may reject a proposed serving promotion. No projected or isolated
result is substituted for a matched whole-response result. Measurements retain
all seven serving metrics when that execution scope exists, with missing cells
explicit. Independent confirmation precedes performance claims/default changes.

## First gates complete

All five slices have executable implementations, regression coverage and retained
measurement records. Their current results are deliberately narrower than serving
promotion. Existing Qwen checkpoints remain the target; the only auxiliary model
is an existing SmolLM2 checkpoint whose proposals undergo exact Qwen verification.

| Slice | Measured result | Current gate |
| --- | --- | --- |
| [Native instructions](../research/execution-capsule-reference.md) | 23.20× less counted Python graph metadata; process peak RSS effectively flat | Complete thin-client memory benefit remains unestablished |
| [Layer-paged state](../research/tiered-decoder-reference.md) | Exact fresh-process recovery; 24× smaller live KV slab; peak RSS rises 0.20–0.77% | Paging CPU/I/O and remaining decoder owners prevent a whole-client memory claim |
| [Checkpoint drafting](../research/checkpoint-drafter-reference.md) | 63.16%/53.70% proposal acceptance; exact target logits/KV; CPU rises 81.68%/92.89% | Both checkpoints, rejected rows and conversion costs block local serving promotion |
| [Preparation credits](../research/correction-stripes-reference.md) | Eight credits lower digit8 local elapsed time 7.46%, with higher endpoint memory; integer kernels regress | Full-response shared-bandwidth integration and confirmation remain required |
| [Stage/phase kernels](../research/stage-kernel-reference.md) | Exact checkpoint logits/KV; learned large-budget dispatch is 3.67% slower than fixed-threshold Metal | Joint resource selection works; an advantage over existing dispatch is unestablished |

The isolated installed wheel passed 266 checks, with one optional skip; the final
drafter/device/runner regression pass passed 55 checks. The compiler passed 220
tests. Rust formatting, compiler/binding Clippy and documentation checks also pass.
Installed runtime sources were compared byte-for-byte with the measured wheel.
Cancellation checks retire owned workers on SIGINT and SIGTERM. A shared fail-fast
cohort lock prevents overlapping participating measurements; the earlier drafter
overlap retains its original evidence and is excluded from corrected timings.

These gates establish bounded mechanisms and negative/tradeoff results. They do
not establish a tenfold client-memory improvement, a persistent SDK conversation,
protected speculative transport or a faster negotiated heterogeneous deployment.
