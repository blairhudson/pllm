# Existing-model execution frontier

Five executable research slices, authorized together. The target remains an
existing open-model checkpoint; auxiliary drafters may help execute that target.
Source, numeric, privacy and one-use material contracts remain explicit.

1. **Load-ready client:** source/build-bound execution metadata and native owners.
   Measure complete construction and client execution, including runtime imports;
   metadata-only savings cannot establish a thin-client result.
2. **Transactional tiered state:** execute the original full-KV attention with
   bounded layer residency, authenticated commits and exact rollback/restart.
   Charge disk, authentication, publication and state/temporary overlap.
3. **Checkpoint drafting:** use an existing smaller checkpoint with a checked
   token boundary, exact target verification and charged rejected work. Establish
   held-out acceptance and complete costs before provider speculation.
4. **Streaming Preparation:** bounded credit-based correction delivery, then
   jointly price kernel batching, masks and transport. READY requires all ordered
   acknowledgements; errors retire every outstanding one-use attempt.
5. **Stage/phase compilation:** synthesize heterogeneous schedules from compatible
   installed implementations and complete measured costs, under joint resource
   bounds. Preserve the source decoder and validate runtime dispatch independently.

Each slice gets a separate implementation/evidence commit. Generated fixtures
test ownership and exact arithmetic; pinned checkpoints test the actual target.
First gates may reject a proposed serving promotion. No projected or isolated
result is substituted for a matched whole-response result. Measurements retain
all seven serving metrics when that execution scope exists, with missing cells
explicit. Independent confirmation precedes performance claims/default changes.
