## Completed MLP gate

The native eligibility, exact generated prefill/decode, one-use retirement and
separate-role SDK checks pass. A six-client Qwen2.5 screen nominated 64-row tiles;
two separate twelve-client confirmations retain all seven serving metrics. Client
peak-RSS medians improve 9.63–17.63% across their workload cells, with matching
outputs and zero observed swap growth. The confirmation runs overlapped on the
host, and TTFT/latency regressions remain explicit. This is a bounded research
tradeoff, not tenfold savings or an automatic Pipeline choice. Contracts and full
cohort separation: [MLP working sets](../research/mlp-working-set-reference.md).

## Benchmark primitive feedback

- **Targets** describe executable scope better than a second probe API. Fixed
  installed executors, immutable cases and existing frontier confirmation suffice.
- **Instrumentation needs its own identity.** Python tracing changes CPU and RSS;
  its observations cannot rank against ordinary response targets.
- **Ownership must be explicit.** Unique metadata, traced increments, native
  buffers, private files and separate endpoint peaks answer different questions.
- **Lifecycle costs need distinct windows.** Publication, initial bootstrap,
  restarted imports and receiver startup remain visible beside online work.
- **Failure tests belong to the state machine.** Partial publication, stale heads,
  replay, rejected acknowledgements and child cleanup are executable gates.
- **Confirmation must retain execution conditions.** Fresh processes alone do not
  make overlapping studies exclusive-host measurements. Keep every cohort and its
  regressions; do not pool salts or copy exploratory timings into missing cells.

The five slices now have executable first gates and evidence. MLP tiling has the
strongest whole-client result; stripes have an isolated memory result worth a
separate transport slice. None establishes a tenfold serving improvement.
